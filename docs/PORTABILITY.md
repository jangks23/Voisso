## ⚠️ 결론 요약 (README·SUBMISSION 담당자 필독)

우리는 README와 제출문에서 **"다른 지자체는 스크레이퍼의 URL만 교체하면 이식된다"** 고 주장해 왔다.

### 그 주장은 사실이 아니다. 문구를 고쳐야 한다.

경상북도청 스크레이퍼의 URL 상수만 안동시 것으로 바꿔 실행하면 **부서 0개**가 나온다.
파이프라인 1단계에서 끝난다. 재현:

```bash
# 실험 1 — URL 상수만 교체 (파싱 규칙은 한 줄도 안 고침)
#   LIST_URL / DETAIL_URL / SOURCE_URL / ROBOTS_URL 을 안동시 것으로 치환
# 결과: parse_department_list() -> 0개
```

다만 **"이식 자체가 어렵다"는 뜻은 아니다.** 안동시는 실제로 이식에 성공했고
(91개 부서 / 1,677건 담당업무), 걸린 시간은 **조사 포함 약 75분**이다.
정확한 주장은 이것이다:

> **"기관마다 파서 어댑터를 하나 써야 한다. 어댑터는 100~150줄이고, 공용 수집
> 계층(요청·robots·캐시·전화번호 살균·출력)은 그대로 재사용된다.
> 같은 CMS를 쓰는 지자체끼리는 URL 교체만으로 이식된다."**

마지막 문장이 중요하다. 안동시 어댑터는 **문경시·구미시에 URL 교체만으로 통했다.**
경북 시군은 소수의 CMS 계열로 수렴하므로, 어댑터 하나가 여러 시군을 커버한다.

## 2. 왜 URL 교체만으로 안 되는가 — 계층별 실측

경상북도청 스크레이퍼를 안동시 페이지에 그대로 먹여 본 결과다.

| 계층 | 경상북도청 | 안동시 | URL만 교체 시 |
|---|---|---|---|
| 목록 → 상세 구조 | 목록 1개 → **부서 상세 96개** | **단일 평면 목록 168페이지** (부서 상세 없음) | ❌ 구조 자체가 다름 |
| 부서 링크 정규식 | `mnu_uid=7332` + `dept_code=` 하드코딩 | `deptCode=` + `mId=` | ❌ **0개 반환** |
| 페이지네이션 | 없음 | `page=N` **필수** | ❌ 개념 자체가 없음 |
| 부서 사무분장 | `<p class="silguk_work">` | **해당 블록 없음** | ❌ 0개 반환 |
| 직원표 헤더 | `소속부서/직책/전화번호/담당업무` | `부서/직위/전화번호/업무 내용` | ⚠️ 헤더 매칭 실패 → 폴백 |
| 직원표 행 파싱 | — | — | 🟡 **우연히 동작** (아래 참조) |
| 전화번호 정규화 | — | — | ✅ 그대로 통함 |

**요약: 3계층 실패, 1계층 우연히 성공, 1계층 성공.**

### 2-1. "우연히 동작"이 가장 위험하다

안동시 표의 헤더에는 `소속`이라는 글자가 없다(`부서`다). 그래서 경북 파서는 헤더 인식에
실패하고 **폴백 헤더 `["소속부서","직책","전화번호","담당업무"]`** 를 쓴다.
안동시의 컬럼 순서가 우연히 같아서 값은 맞게 들어간다. **설계가 아니라 운이다.**

게다가 안동시 HTML에는 이런 게 있다:

```html
<th scope="col" class="list_position">직위</th>
<!-- <th scope="col" class="list_name">이름</th> -->   ← 주석 처리
<th scope="col" class="list_tel">전화번호</th>
```

경북 파서의 셀 정규식은 **주석 안의 `<th>`까지 잡는다.** 그래서 헤더는 5칸, 본문은 4칸으로
어긋난다. 만약 안동시가 `부서` 대신 `소속부서`라고만 썼다면 헤더 인식에 성공했을 것이고,
그 순간 **전화번호 칸에 담당업무가 들어가고 담당업무는 빈 값이 되는** 조용한 오파싱이
발생했을 것이다. 에러 없이. 검증 로그도 통과하면서.

구미시는 이 함정이 더 뚜렷하다. 헤더가 **6칸**(`부서/담당/직위/이름/전화번호/업무 내용`)인데
렌더링되는 `<td>`는 **4칸**이다.

**그래서 안동 어댑터는 헤더를 아예 믿지 않고 위치로 읽되, 렌더링된 `<td>` 수가 4가
아니면 그 행을 버리고 이상 건수를 실행 끝에 보고한다.** 조용히 앞 4칸을 잘라 쓰면
틀린 데이터를 정상인 척 내보내게 된다.

## 3. 이식 과정에서 실제로 터진 문제들

문서에 없던, 직접 부딪혀서 알게 된 것들이다.

### 3-1. `IncompleteRead` — 공용 `fetch()` 의 재시도 그물이 새고 있다

안동시는 응답을 chunked 로 내려주는데 간헐적으로 끊긴다.

```
http.client.IncompleteRead(679928 bytes read)    # 실제 발생
```

경북 `fetch()` 의 재시도는 `(URLError, HTTPError, OSError)` 만 잡는다.
**`IncompleteRead` 는 `HTTPException` 계열이라 이 그물에 안 걸리고 그대로 크래시한다.**

더 위험한 변형이 있다. 끊긴 응답이 예외 없이 돌아오면 **표 일부만 담긴 HTML을 정상으로
착각해 조용히 적은 행을 수집한다.** 그래서 안동 어댑터는 (1) 예외 그물을 넓히고
(2) 페이지 끝 표식(`</html>`)이 있는지 검증한 뒤에만 캐시에 쓴다. 잘린 캐시는 버리고 다시 받는다.

> 🔴 **이건 경상북도청 경로에도 잠재된 결함이다.** 지금은 gb.go.kr 이 안정적이라 안 터질
> 뿐이다. P3에게 `scrape_gb_departments.py` 의 `fetch()` 에도 같은 보강을 권한다.
> (본 담당은 소유 경로가 아니라 손대지 않았다.)

### 3-2. 동시 요청 4개에서 응답이 끊겼다

워커 4로 돌렸을 때 `IncompleteRead` 가 재현됐다. **2로 낮추니 168페이지가 무사히 들어왔다.**
안동 어댑터의 기본값은 `WORKERS = 2` 다. 요청 간 0.3초 지연은 경북 쪽 전역 레이트리밋을
그대로 공유한다.

### 3-3. 문경시는 TLS 인증서 체인이 깨져 있다 (파이썬에서 접속 불가)

```
ssl.SSLCertVerificationError: unable to get local issuer certificate
```

`openssl s_client` 로 확인한 결과 **문경시는 리프 인증서만 보내고 중간 CA를 보내지 않는다.**

```
 0 s:CN=*.gbmg.go.kr
   i:CN=Sectigo RSA Organization Validation Secure Server CA   ← 이 중간 인증서가 안 옴
```

비교로 안동시는 체인 3장을 온전히 보낸다. 브라우저와 `curl` 은 AIA 로 중간 인증서를
따로 받아와 복구하지만 **파이썬 `urllib` 은 하지 않는다.**

**이것은 문경시 서버 설정 문제이지 우리 코드 문제가 아니다.**
인증서 검증을 끄는 방식으로 우회하지 않았다. 공공기관에 이관될 코드에서
`verify=False` 는 남기면 안 된다. 이식하려는 담당자는 둘 중 하나로 해결해야 한다.

- 문경시에 중간 인증서 체인 설정을 요청한다 (**정공법 · 권장**)
- 중간 인증서를 받아 `SSL_CERT_FILE` 로 지정한다 (임시 조치)

### 3-4. `class="bod_list"` vs `class="bod_list staff"`

같은 CMS인데 문경시는 테이블 class 가 `bod_list staff` 다. 정규식이
`class="bod_list"` 로 딱 붙어 있으면 **한 글자 차이로 조용히 0행을 반환한다.**
안동 어댑터는 `\bbod_list\b` 로 느슨하게 잡는다.

### 3-5. 안동시 웹방화벽이 일반 도구를 차단한다

WebFetch 같은 범용 페처는 **웹방화벽 차단 페이지**를 받는다.
User-Agent 를 명시한 직접 요청은 정상 동작한다. 우리 크롤러는 이미
`Voisso-GB-OpenData-Crawler/1.0 (…)` 를 붙이고 있어 문제되지 않았다.

이 규칙으로 `parent` 를 복원했다. 확인된 최상위 조직 10개(관광문화국·경제산업국·평생복지국·

그 하위 과가 연결된다. `상위조직 미분류 13` 은 시장 직속 실(기획예산실·공보실·청렴감사실·
지방시대정책실)과 직속기관·사업소(의회사무국·시립도서관·하회마을관리사무소 등)로,
**상위가 없는 게 정상**이다. 숫자를 부풀리지 않으려고 최상위 조직과 미분류를 나눠 센다.

**읍면동 24곳이 포함된다.** 강남동·풍산읍·와룡면 등. 실제 생활 민원의 1차 창구라
[`GOAL.md`](../GOAL.md) H3 "시군 단위 확장"에 직접 기여한다.

### 개인정보 처리

계약서 3절을 그대로 적용했다.

- 전화번호는 공개 산출물에 넣지 않는다. **`ADPHONE_0001` 토큰**으로 치환한다.
  (경북 `PHONE_` 과 접두사를 분리해 두 데이터셋의 토큰이 섞이지 않게 한다.)
- 실제 매핑은 `data/private/andong_phone_map.json` — **gitignore 대상.**
- 가짜 번호를 생성하지 않는다. 반드시 토큰 형식.
- 담당업무 **본문에 섞인 번호**도 제거한다. 살균은 `voisso/routing/privacy.py` 의
  `scrub()` **하나만** 재사용한다. 새로 만들지 않았다.
  (경북 소방본부 내선번호 111건이 본문에 섞여 있던 사고의 재발 방지)
- 실명 컬럼은 존재하지 않는다. 안동시 HTML의 `이름` `<th>` 는 **주석 처리되어
  렌더링되지 않는다.** 우리 파서는 본문 `<td>` 만 읽으므로 애초에 수집 대상이 아니다.
- 검증 결과 **본문 전화번호 잔존 0건.** `scrub()` 오탐(`***` 치환)도 **0건** —
  연도 범위 등을 잘못 지운 흔적이 없다.

### 라이선스 (docs/DATA_LICENSE.md 형식)

**안동시는 공공누리 제1유형(출처표시)이다. 경상북도청(제3유형 추정)보다 명확히 자유롭다.**

근거는 추정이 아니라 **직원업무 검색 페이지 자체에 부착된 마크**다.

## 5. 크롤링 예의 — 실제로 지킨 것

| 항목 | 기준 | 실제 |
|---|---|---|
| robots.txt | 수집 전 확인 | ✅ 매 실행 시 확인, 금지면 종료 코드 2로 중단 |
| 동시 요청 | 4개 이하 | ✅ **2개** (4에서 응답이 끊겨 낮춤) |
| 요청 간 지연 | 0.3초 이상 | ✅ 0.3초 전역 레이트리밋 (경북 쪽과 공유) |
| User-Agent | 명시 | ✅ `Voisso-GB-OpenData-Crawler/1.0 (JunctionX Korea; …)` |
| Crawl-delay | 있으면 우선 | ✅ robots 의 값이 크면 그 값을 따름 |
| 캐시 | 재실행 시 재요청 안 함 | ✅ `data/raw/andong/` · `--refresh` 로만 재수집 |

안동시 robots.txt 는 `/sys*`, `/cmm/fms/*`, `*/bbs/*`, `/saeol/`, `/search/*` 를 금지한다.
우리가 쓰는 `/portal/staff/list.do` 와 `/portal/contents.do` 는 **금지 목록에 없다.**

전체 수집은 **170 요청 / 3분 10초** 였다. 조직 개편은 연 1~2회이므로 상시 크롤링이 아니다.

## 6. 일반화 구조 제안

이번엔 **경상북도청 경로를 건드리지 않는 쪽**을 택했다.
`scripts/scrape_gb_departments.py` 는 **한 줄도 수정하지 않았고**, 안동 어댑터가
그 모듈을 import 해 공용 유틸을 재사용한다.

```
scripts/
  scrape_gb_departments.py       # 손대지 않음. 공용 유틸의 사실상 제공자
  scrape_andong_departments.py   # 안동 어댑터 — 위에서 5개 함수를 import
```

**재사용된 것 (그대로):** `clean_text` · `normalize_phone` · `is_phone_like` ·
`cached_fetch` 의 캐시 규약 · `INLINE_PHONE_RE` · `USER_AGENT` · 전역 레이트리밋 ·
`voisso.routing.privacy.scrub()`

**기관마다 새로 써야 하는 것 (≈150줄):** 목록/상세 URL · 부서 열거 방식 ·
표 파싱 · 계층 복원 · 라이선스 상수 · 검증 임계값

### 다음 단계 (권장, 이번 범위 밖)

지금 구조의 솔직한 한계는 **안동 어댑터가 경북 스크레이퍼를 import 한다**는 점이다.
공용 유틸의 소유자가 "경북 전용 스크립트"인 건 오래 갈 모양이 아니다. 다만
**병렬 작업 중 P3 소유 파일을 재구조화하는 위험**이 이득보다 커서 지금은 미뤘다.
([`docs/CONTRACT.md`](./CONTRACT.md) 2절: `scripts/` 는 P3 소유)

해커톤 이후 P3와 합의해 이렇게 가르는 것을 권한다.

```
scripts/
  scraper_core.py       # 요청·robots·캐시·레이트리밋·토큰화·출력  (기관 무관)
  sites/
    gb.py               # 경상북도청 어댑터
    andong.py           # 안동시 어댑터
    mungyeong.py        # 문경시 어댑터 (안동 것 URL만 교체)
  scrape_org.py         # python3 scripts/scrape_org.py --site andong
```

어댑터가 구현할 인터페이스는 이미 안동 작업에서 자연스럽게 드러났다.

```python
BASE / STAFF_URL / ORG_URL / SOURCE_URL / ROBOTS_URL   # URL 상수
LICENSE / SOURCE_ORG / ATTRIBUTION                      # 라이선스 상수
MIN_DEPARTMENTS / MIN_STAFF_ROWS / EXPECTED_COLUMNS     # 검증 임계값
parse_org_tree(page)   -> dict[부서명, 상위조직명]
parse_total_pages(page)-> int
parse_staff_rows(page) -> list[{department, position, phone, duty}]
```

**전제 조건: 리팩터링 후 `python3 scripts/scrape_gb_departments.py` 가 그대로
96개 부서를 뽑아야 한다.** 이번 작업에서는 산출물이 `fetched_at` 을 빼고
**바이트 단위로 동일**함을 확인했다.
