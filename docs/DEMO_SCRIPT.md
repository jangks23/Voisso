# Voisso 데모 대본 (촬영 · 시연용)

> **목표 길이 2분 50초.** 5단계 + MCP 마무리. (상한 3분을 넘기지 마라)
> 각 단계는 심사 기준 하나씩을 증명한다. 설명하지 말고 **보여준 다음** 한 줄로 못박는다.
>
> **클라이맥스는 5단계(담당자 핸드오프)다.** 앞의 네 단계는 거기로 가는 길이다.
> 시간이 모자라면 1~3단계를 깎아라. **5단계를 깎지 마라.**
>
> ⚠️ 이 문서의 대본은 **현재 동작하는 기능**만 담았다. 아직 작업 중인 것은 🚧 로 표시했다.
> 촬영 시점에 완성되지 않았다면 그 컷은 빼고 간다. 없는 걸 있는 척하면 심사에서 더 크게 잃는다.
> **지금 🚧 인 것은 5단계(담당자 핸드오프) 하나뿐이다.** 1~4단계와 6단계는 실행해서 확인했다.

| **1. 사투리 → STT 오인식 → 정규화 교정** | 0:15–0:47 | 32초 | 혁신성 및 차별성 (20%) |
| **2. AI가 사투리로 되물으며 슬롯 채움** | 0:47–1:15 | 28초 | 기술적 완성도 (25%) |
| **3. 통화 종료 → 민원카드 → 사무분장 원문 근거** | 1:15–1:42 | 27초 | 공공데이터 실사용 · 필수 조건 |

프로토타입 보너스(10%)는 **영상 전체가 실제 화면**이라는 사실로 증명된다. 슬라이드를 섞지 마라.

**왜 5단계에 40초를 몰아주는가.** 1~4단계는 "AI가 민원을 잘 받는다"까지다. 그것만으로는
공공기관이 도입하지 않는다. 5단계가 **"그래서 사람이 어떻게 이어받는가"** 에 답하고,
동시에 방언 레이어가 AI 부품이 아니라 **사람과 사람 사이의 통역기**라는 것을 보여준다.
심사위원이 마지막에 기억할 장면은 여기다. 앞을 3초씩 깎아서라도 여기를 지켜라.

## 0. 문제 제기 — 0:00–0:15 ⏱ 15초

**첫 15초가 전부다.** 아키텍처 다이어그램으로 시작하지 마라. 문제를 던지고 곧바로 사투리를 들려준다.

| | |
|---|---|
| **화면** | 검은 배경에 흰 텍스트 두 줄. 그다음 **바로** 통화 화면으로 컷 전환. |
| **자막** | `경상북도, 65세 이상 인구 비율 전국 최상위권` → `민원 창구는 여전히 ARS입니다` |

**내레이션**

> "경북 어르신이 도청에 전화를 겁니다. 1번 도로, 2번 상하수도, 3번… 끝까지 듣고 자기 민원이 몇 번인지 골라야 합니다. 잘못 누르면 처음부터. 그리고 그 다음 안내는, 표준어로만 나옵니다."

**연출 주의**
- 이 15초 동안 Voisso가 무엇인지 **설명하지 않는다.** 문제만 던진다.
- 0:15에 곧바로 어르신 목소리가 나와야 한다. 정적을 두지 마라.

## 1. 사투리 → STT 오인식 → 정규화 교정 — 0:15–0:47 ⏱ 32초

**증명 대상: 혁신성 및 차별성 (20%)**

| | |
|---|---|
| **화면** | `web/call/index.html` 통화 화면. 발화 → STT 원문 → 정규화 결과가 순서대로 뜬다. |
| **핵심 컷** | STT 원문과 정규화 결과가 **동시에 보이는 순간.** 여기서 1초 멈춘다. |

**입력 문장** (실측 검증된 예시)

```
어르신 발화 :  비가 오면 집앞 도로에 물이 안 빠져가 큰일이라예
정규화 결과 :  비가 오면 집앞 도로에 물이 안 빠져서 큰일이에요
```

**내레이션**

> "'물이 안 빠져가 큰일이라예.' 음성인식은 이걸 그대로 받아씁니다. 표준어 기준으로 학습된 모델이니까요. Voisso는 여기에 방언 레이어를 하나 더 둡니다. 경북 방언 어휘 367개와 어미 규칙 70개로 표준어로 되돌린 다음, 그 결과를 AI에게 넘깁니다."

**못박는 한 줄**

> "어르신이 말을 고치는 게 아니라, 시스템이 알아듣습니다."

**연출 주의**
- 화면에 **원문과 교정문을 나란히** 띄워라. 이 대비가 이 컷의 전부다.
- `-가` → `-서`, `-라예` → `-이에요` 처럼 **바뀐 부분에 하이라이트**를 넣으면 좋다.
- 음성 입력이 준비되지 않았다면 **텍스트 입력으로 진행한다.** 문장이 같으면 메시지는 동일하다.

## 2. AI가 사투리로 되물으며 슬롯을 채움 — 0:47–1:15 ⏱ 28초

**증명 대상: 기술적 완성도 (25%)**

| | |
|---|---|
| **화면** | 통화 화면 우측 슬롯 패널. 4개 항목이 차례로 채워진다. |
| **슬롯** | `무슨 일` · `어디서` · `언제부터` · `연락처` |

**대화 흐름**

```
AI    :  어데신지 여쭤봐도 될까예?          ← 표준어 응답을 경북 사투리로 변환해 출력
어르신:  안동 옥동인데예
AI    :  언제부터 그랬는교?
어르신:  장마 지나고부터 계속 그래예
```

**내레이션**

> "AI는 사투리로 되묻습니다. 무슨 일인지, 어디인지, 언제부터인지, 연락처. 네 가지가 채워지면 통화를 마무리합니다. 한 항목은 최대 두 번까지만 묻고, 그래도 안 나오면 넘어갑니다. 어르신을 심문하지 않기 위해서입니다."

**못박는 한 줄**

> "버튼을 누를 필요가 없습니다. 그냥 말하면 됩니다."

**연출 주의**
- 슬롯이 **하나씩 체크되는 애니메이션**이 이 컷의 시각적 핵심이다. 패널이 화면에 반드시 들어오게 프레이밍하라.
- 되묻는 문장이 사투리로 나온다는 점을 자막으로 강조하라 (`될까요?` → **`될까예?`**).

## 3. 통화 종료 → 민원카드 → 사무분장 원문 근거 — 1:15–1:42 ⏱ 27초

**증명 대상: 공공데이터 실사용 (필수 조건) · 공공부문 활용 가능성**

이 컷이 **이 프로젝트에서 가장 중요하다.** 여기서 공공데이터를 실제로 쓴다는 걸 증명한다.

| | |
|---|---|
| **화면** | 통화 종료 → 민원카드 생성. 카드의 `배정 근거` 인용 블록을 **확대**한다. |

**화면에 뜨는 값** (실측)

```
요약   : 안동 옥동 주택가 배수 불량, 강우 시 반복
배정   : 기후환경국 맑은물정책과 (주무관)   ← 확신도 낮음: 후보 3곳 함께 제시
근거   : ◦ 하수도 재난재해대책(호우, 태풍 등) 수립 및 시행 …
대안   : 농축산유통국 스마트농업혁신과 (0.586) — 근거: 배수개선사업
```

> **"확신 없음"이 뜨는 건 사고가 아니다.** 배수 불량은 하수도 소관일 수도, 농업기반
> 정비 소관일 수도 있다. 억지로 하나를 고르지 않고 근거와 함께 후보를 내미는 것이
> 설계 의도다. **내레이션에서 이걸 약점처럼 말하지 마라.**

**내레이션**

> "통화가 끝나면 민원카드가 만들어집니다. 여기서 중요한 건 맨 아래 '근거' 한 줄입니다. 이건 AI가 지어낸 설명이 아니라, **경상북도청이 공개한 그 부서의 사무분장 원문**입니다. 저희는 도청 조직도에서 96개 부서, 1,866건의 담당업무를 수집해 라우팅 근거로 씁니다."

**못박는 한 줄**

> "AI가 그렇게 판단했다, 로 끝나지 않습니다. 왜 그 부서인지가 공공데이터 원문으로 남습니다."

**연출 주의**
- `근거` 블록을 **화면 가득 확대**하라. 이 한 줄이 심사 기준 두 개(공공데이터 실사용 + 공공부문 활용 가능성)를 동시에 친다.
- 확신도가 낮을 때 **후보를 여러 개 제시**하는 화면이 있다면 0.5초라도 스쳐라. "단정하지 않는다"는 신뢰 요소다.

## 4. 담당자 대시보드에 실시간 도착 — 1:42–1:57 ⏱ 15초

**증명 대상: 공공부문 활용 가능성 (25%)**

| | |
|---|---|
| **화면** | 좌: 통화 화면 / 우: `web/dashboard/index.html`. **분할 화면**으로 둘을 함께 보여준다. |

**내레이션**

> "같은 시각, 담당 공무원 화면입니다. 방금 그 민원이 부서에 배정되어 올라옵니다. 담당자가 가장 먼저 보는 것도 그 근거 문장입니다. 왜 나한테 왔는지 한 줄로 확인하고, 아니면 바로 재배정합니다."

**못박는 한 줄**

> "잘못 배정된 민원이 부서를 떠도는 일을 줄입니다."

**연출 주의**
- 분할 화면이 이 컷의 전부다. 통화 종료 → 대시보드 등장이 **끊김 없이** 이어져야 한다.
- 대시보드는 기본값이 실서버 연동이다(`web/dashboard/config.js` 의 `USE_MOCK: false`).
  `python3 -m server` 로 띄운 뒤 `http://localhost:8000/dashboard/` 로 열면 방금 그 통화가
  **4초 안에** 목록 맨 위에 뜬다. 샘플 데이터로 찍고 싶을 때만 `?mock=1` 을 붙인다.
- **여기서 화면을 닫지 마라.** 이 분할 화면 그대로 5단계로 넘어간다. 컷을 나누면
  "같은 순간에 양쪽에서 벌어지는 일"이라는 인상이 깨진다.

## 5. 담당자가 통화를 잇는다 — 양방향 통역 — 1:57–2:37 ⏱ 40초

**증명 대상: 공공부문 활용 가능성 (25%) · 혁신성 (20%) — 이 영상의 클라이맥스**

> 🚧 **이 기능은 현재 작업 중이다** (P6 서버 · P7 통화화면 · P8 대시보드 동시 진행).
> 계약은 [`docs/CONTRACT.md`](./CONTRACT.md) 5-B절에 고정되어 있다.
> **촬영 시점에 동작하지 않으면 이 컷을 통째로 빼라.** 대체 방안은 이 절 맨 아래에 있다.
> 없는 걸 있는 척하면 심사에서 더 크게 잃는다.

| | |
|---|---|
| **화면** | 4단계의 **분할 화면을 그대로 유지**한다. 좌: 어르신 통화 화면 / 우: 담당자 대시보드 |
| **핵심 컷** | 담당자가 **표준어로 친 문장**이 어르신 화면에 **사투리로 뜨는 순간.** 두 화면을 한 프레임에 담아 1.5초 멈춘다. |

**흐름**

```
① 담당자가 민원카드에서 [통화 잇기] 를 누른다  (우측 화면)
② 이름·부서를 입력하고 연결                     POST /api/handoff/{id}/start
③ 어르신 화면에 배지가 뜬다 → "지금부터 담당자가 직접 응대합니더"
   같은 순간 AI 는 발화를 멈춘다.
④ 담당자가 표준어로 친다 → 어르신은 사투리로 받는다
⑤ 어르신이 사투리로 답한다 → 담당자는 표준어로 받는다
```

**주고받는 문장** (아래는 `voisso.dialect` 를 실제로 실행해 얻은 출력이다. 지어내지 마라)

```
담당자가 친 것   :  기후환경국 맑은물정책과 담당자입니다. 접수 내용 확인했습니다.
어르신이 듣는 것 :  기후환경국 맑은물정책과 담당자입니더. 접수 내용 확인했습니더.

담당자가 친 것   :  그러면 내일 아침에 현장에 나가 보겠습니다. 조금만 기다려 주세요.
어르신이 듣는 것 :  그라믄 내일 아침에 현장에 나가 보겠습니더. 조금만 기다려 주이소.
                    └ 그러면→그라믄 · 주세요→주이소 · -습니다→-습니더

어르신이 말한 것 :  낼 오신다 캅니꺼?
담당자가 보는 것 :  내일 오신다 합니까?
                    └ 낼→내일 · 캅니꺼→합니까
```

**내레이션**

> "담당자가 '통화 잇기'를 누릅니다. 여기서부터 AI 는 말하지 않습니다. 사람이 직접 응대합니다.
> 그런데 담당자는 **표준어로 칩니다.** 어르신 화면에는 **사투리로** 갑니다. 반대도 마찬가지입니다.
> 어르신이 '낼 오신다 캅니꺼' 라고 하면 담당자는 '내일 오신다 합니까' 로 읽습니다.
> 저희가 만든 방언 레이어는 AI 가 쓰는 부품이 아니라, **사람과 사람 사이의 통역기**입니다.
> 담당자가 경상도 사람이 아니어도, 어르신과 그냥 대화할 수 있습니다."

**못박는 한 줄** — *이 영상에서 가장 중요한 한 문장이다. 또박또박 읽어라.*

> "AI 에게 전권을 주는 게 아닙니다. **접수까지만 AI 가 돕고, 처리는 사람이 책임집니다.**
> 'AI 가 민원을 처리한다' 는 공공기관이 받아들이지 않습니다. 하지만
> 'AI 가 접수를 돕고 담당자가 처리한다' 는 — 내일부터 쓸 수 있습니다."

**연출 주의**
- **두 화면이 한 프레임에 같이 보여야 의미가 산다.** 한쪽씩 번갈아 잡으면 통역이라는 사실이
  전달되지 않는다. 화면 배치는 아래 「촬영 체크리스트 → 3. 화면」의 **5단계 분할 배치**를 따른다.
- 담당자가 타이핑하는 손과 어르신 화면에 사투리가 뜨는 순간을 **끊지 말고 한 컷으로** 잡아라.
  컷을 나누면 "편집으로 만든 것 아니냐"는 의심이 생긴다.
- 변환된 어절(`그라믄` · `주이소` · `캅니꺼`)에 **자막 하이라이트**를 넣어라. 지나가면 못 본다.
- AI 정지 배지("지금부터 담당자가 직접 응대합니더")를 **반드시 화면에 잡아라.** 누가 말하고
  있는지 헷갈리면 그 자체로 신뢰 문제가 된다 (계약서 5-B절).
- 담당자 이름은 **가명**을 쓴다. 실명·실제 연락처가 화면에 잡히면 안 된다.

**동작하지 않을 때의 대체 (우선순위 순)**

1. **한쪽 방향만 동작하면 그쪽만 보여준다.** 담당자→어르신(사투리 출력)이 더 극적이다.
   내레이션에서 반대 방향은 "같은 방식으로 되돌립니다" 로 한 문장만 언급한다.
2. **서버만 되고 UI 가 안 되면** `curl` 로 `POST /api/handoff/{id}/message` 를 보내고
   어르신 화면에 사투리로 뜨는 것만 잡는다. 터미널이 화면에 나오는 건 감점 요인이 아니다.
3. **전부 안 되면 이 컷을 뺀다.** 4단계에서 곧바로 6단계(MCP)로 간다. 총 길이는 **2분 10초**가
   되고, 그래도 완결된 대본이다. 3단계(민원카드 근거)에 5초를 더 주면 **2분 15초**다.
   **내레이션에서 핸드오프를 언급조차 하지 마라.** 로드맵으로 말하고 싶으면
   영상이 아니라 제출문(`SUBMISSION.md`)에서 말한다.

## 촬영 체크리스트

시연 **30분 전**에 순서대로 확인한다.

### ⚡ 원터치 실행

```bash
./scripts/demo.sh                # 데이터 준비 → 서버 기동 → 브라우저 열기
```

**둘 다 완성되어 동작한다.** `demo.sh` 는 7단계를 밟으며 무엇을 하는지 출력하고,
실패하면 다음에 무엇을 하면 되는지 알려주고 멈춘다. 아래 수동 절차는 **이 스크립트가
실패했을 때 어디를 봐야 하는지** 알기 위한 것이다.

### 1. 데이터 · 서버

- [ ] **데이터 존재 확인** — 없으면 라우팅이 전부 실패한다. 가장 먼저 본다.
  ```bash
  python3 -c "from voisso.data import load_departments as f; d=f(); print('부서', len(d['departments']), '| 수집', d['meta']['fetched_at'])"
  ```
  없으면 → `python3 scripts/scrape_gb_departments.py` (약 35초, 네트워크 필요)
- [ ] **라우팅 동작 확인** — 데모에 쓸 그 문장으로 미리 돌려본다.
  ```bash
  python3 -c "from voisso.routing import route; r=route('비가 오면 집앞 도로에 물이 안 빠져가 큰일이라예'); print(r['matches'][0]['full_name'], '|', r['matches'][0]['evidence'])"
  ```
- [ ] **MCP 셀프테스트 통과** — `python3 -m mcp_server.selftest`
      마지막 줄이 `N/N 통과` 여야 한다. **실패 항목이 있으면 그 화면은 찍지 마라.**
      대신 Claude Desktop 실사용 컷으로 5단계를 대체한다.
- [ ] **API 서버 기동** — `pip install -r requirements.txt` 후 `python3 -m server`.
      상태 확인은 헬스체크 한 줄이면 된다. `degraded: true` 면 무엇이 빠졌는지 `missing_keys` 가 알려준다.
      ```bash
      curl -s localhost:8000/api/health | python3 -m json.tool
      ```
- [ ] **통합 리허설 1회** — `python3 scripts/rehearsal.py --runs 3` 이 서버 기동부터
      민원카드·대시보드 반영까지 브라우저 없이 3회 재현하고 `docs/REHEARSAL.md` 에 기록한다.
      **여기서 실패하면 촬영을 시작하지 마라.**
- [ ] **전화번호 매핑 확인** — `data/private/phone_map.json` 이 있으면 실번호, 없으면 대표번호
      `1522-0120` 로 표시된다. **영상에 실제 공무원 번호가 잡히지 않게** 할 거면 일부러 비워도 된다.
- [ ] 🚧 **담당자 핸드오프 동작 확인 (5단계)** — 작업 중인 기능이다. 촬영 직전에 반드시 찍어본다.
      민원카드 하나를 만든 뒤 `complaint_id` 를 넣고 아래를 돌려서, **네 줄이 다 나오면** 촬영 가능이다.
      하나라도 실패하면 5단계 절의 「동작하지 않을 때의 대체」로 간다.
      ```bash
      CID=0001   # 방금 만든 민원카드 번호
      curl -s -X POST localhost:8000/api/handoff/$CID/start \
           -H 'Content-Type: application/json' \
           -d '{"officer_name":"홍길동","department":"기후환경국 맑은물정책과"}'
      curl -s -X POST localhost:8000/api/handoff/$CID/message \
           -H 'Content-Type: application/json' \
           -d '{"role":"officer","text":"그러면 내일 아침에 현장에 나가 보겠습니다. 조금만 기다려 주세요."}'
      curl -s localhost:8000/api/handoff/$CID | python3 -m json.tool
      ```
      마지막 응답의 메시지에 `dialect` 와 `standard` 가 **둘 다** 있고, `dialect` 쪽이
      `그라믄 … 주이소` 로 바뀌어 있어야 한다. 이게 5단계 화면의 실체다.
- [ ] 🚧 **양방향인지 확인** — 위에서 `"role":"caller","text":"낼 오신다 캅니꺼?"` 를 보내고
      `standard` 가 `내일 오신다 합니까?` 로 오는지 본다. 한쪽 방향만 되면 대체안 1번으로 간다.

### 2. 브라우저 · 마이크

- [ ] **Chrome 사용** (필수). 통화 UI는 `getUserMedia` + `MediaRecorder` 로 마이크를 잡는다.
      Safari는 코덱·권한 동작이 달라 당일 변수를 만든다.
- [ ] **`file://` 로 열지 마라.** 마이크는 보안 컨텍스트를 요구한다. 반드시 로컬 서버로 연다.
  ```bash
  python3 -m server                # 통화 UI·대시보드·API 를 한 프로세스가 서빙한다
  # → http://localhost:8000/call/        (촬영은 이 주소로 한다)
  # → http://localhost:8000/dashboard/
  ```
  API 서버 없이 목 모드만 보여줄 거라면 정적 서버로도 열린다
  (`python3 -m http.server 8080` → `http://localhost:8080/web/call/?mock=1`).
  **다만 촬영 주소를 둘로 섞지 마라.** 서버가 살아 있는 한 `:8000/call/` 하나로 간다.
- [ ] **마이크 권한 미리 허용** — 촬영 중 권한 팝업이 뜨면 그 컷은 버린다. 사전에 한 번 눌러 둔다.
- [ ] **입력 장치 확인** — 시스템 설정에서 사용할 마이크가 선택돼 있는지. 외장 마이크 권장.
- [ ] **알림 끄기** — macOS 방해금지 모드. 슬랙·메일 배너가 뜨면 다시 찍어야 한다.

### 3. 화면

- [ ] **해상도 1920×1080 고정.** 심사 영상은 대개 축소 재생된다. 그 이상은 글씨가 작아진다.
- [ ] **테마: 라이트 모드로 통일한다.**
      통화 UI와 대시보드 **둘 다 `prefers-color-scheme` 자동 전환**을 지원한다.
      시스템 테마가 바뀌면 두 화면 톤이 어긋난다. **촬영 전 시스템을 라이트로 고정**하라.
      (어두운 배경을 원하면 둘 다 다크로 — **섞지만 않으면 된다.**)
- [ ] **브라우저 확대 125~150%** — 어르신 대상 서비스인데 글씨가 작으면 설득력이 떨어진다.
- [ ] **북마크바·확장프로그램 아이콘 숨기기.** 전체화면(⌃⌘F) 권장.
- [ ] **개인정보 점검** — 화면에 실제 전화번호, 개인 계정, 사내 URL이 잡히지 않는지 **녹화 전 한 번 훑는다.**

#### 4~5단계 분할 배치 (이번 대본에서 가장 까다로운 세팅)

5단계는 **두 화면에서 동시에 벌어지는 일**이 핵심이라, 한 프레임에 둘이 같이 들어와야 한다.
번갈아 잡으면 "통역"이라는 사실이 전달되지 않는다. 1920×1080 기준으로 이렇게 잡는다.

```
┌──────────────────────────┬──────────────────────────┐
│  좌 960px                │  우 960px                │
│  어르신 — 통화 화면       │  담당자 — 대시보드        │
│  localhost:8000/call/    │  localhost:8000/dashboard/│
│                          │                          │
│  · 확대 125%             │  · 확대 100%             │
│    (어르신용 큰 글씨가    │    (민원카드 + 통역 입력  │
│     그대로 근거가 된다)   │     창이 함께 보여야 한다)│
│  · 말풍선 영역이 세로     │  · 상세 패널을 **미리 연  │
│    중앙에 오게            │    상태**로 대기          │
└──────────────────────────┴──────────────────────────┘
```

- [ ] **창 두 개를 정확히 반씩 배치한다.** macOS 는 `Rectangle` 같은 창 관리 도구의
      "왼쪽 절반 / 오른쪽 절반" 단축키가 가장 빠르다. 손으로 끌면 몇 픽셀씩 어긋나고
      그 틈이 영상에서 눈에 띈다.
- [ ] **두 창의 확대율을 다르게 잡는다.** 통화 화면 125%, 대시보드 100%.
      대시보드까지 키우면 통역 입력창이 접히거나 스크롤이 생긴다.
- [ ] **테마를 양쪽 다 라이트로 고정.** 두 화면이 한 프레임에 있으므로 톤이 어긋나면
      바로 티가 난다 (둘 다 `prefers-color-scheme` 자동 전환을 지원한다).
- [ ] **대시보드는 상세 패널을 연 채로 대기.** 5단계에서 [통화 잇기] 버튼까지 도달하는
      클릭 수를 줄인다. 마우스가 화면을 헤매는 컷은 그대로 시간 낭비다.
- [ ] **전환 시점을 정해 둔다.** 1~3단계는 통화 화면 **전체화면**, 3단계에서 민원카드가
      뜨는 순간 분할로 전환해 4·5단계를 **끊지 않고** 간다. 5단계에서 컷을 나누지 마라.
- [ ] **커서를 크게.** 접근성 설정에서 포인터 크기를 키우면 어느 화면을 조작 중인지
      시청자가 따라올 수 있다. 두 화면을 오가는 컷에서 특히 중요하다.

### 4. 녹화 직전 최종 리허설

- [ ] 0단계부터 5단계까지 **한 번 끊김 없이** 돌려본다.
- [ ] 총 길이를 재고 2분 30초를 넘으면 **2단계 대화 턴을 줄인다** (여기가 가장 늘어나는 구간).
- [ ] 백업 녹화본이 있는지 확인 (아래 실패 대비책).

| **API 서버 다운** | 통화 화면이 "서버 응답 없음" | **목 모드로 즉시 전환.** 전 과정이 그대로 시연된다. | 서버가 아직 살아 있으면 주소 끝에 `?mock=1` → `http://localhost:8000/call/?mock=1`. <br>**서버가 죽었으면 그 페이지 자체를 못 받는다.** 그때는 파일을 직접 연다 → `open web/call/index.html` (`file://` 는 자동으로 목 모드다). 마이크는 안 되므로 **텍스트 입력으로 진행**한다. |
| **마이크 불통 / 권한 거부** | 녹음 버튼이 안 먹음 | **텍스트 입력 모드.** 같은 문장을 타이핑한다. 정규화·라우팅·민원카드는 동일하게 동작한다. | 화면 하단 텍스트 입력창 사용. 내레이션에서 "음성 대신 텍스트로 보여드리겠습니다" 한마디만 넣는다. |
| **타입캐스트 한도 초과** | 음성 응답이 안 나옴 | **텍스트 모드.** `VOISSO_TTS_PROVIDER=none` 이면 화면에 텍스트만 뜬다. 대본의 메시지는 하나도 안 잃는다. | `.env` 에서 `VOISSO_TTS_PROVIDER=none` 으로 바꾸고 서버 재기동. **접두사는 `VOISSO_` 다** — `VOISO_` 로 쓰면 아무 효과가 없다. |
| 🚧 **핸드오프 미완성 / 중간에 깨짐** | [통화 잇기] 가 없거나 눌러도 반응 없음 | **5단계를 뺀다.** 4단계 → 6단계(MCP)로 바로 간다. 총 2분 10초짜리 완결된 대본이 남는다. | 5단계 절의 「동작하지 않을 때의 대체」 3단계를 순서대로 시도한다. 한쪽 방향만 살아 있으면 담당자→어르신(사투리 출력)만 보여준다. **로드맵으로 얼버무리지 말고 아예 언급하지 마라.** |
| **STT가 엉뚱하게 받아씀** | 정규화 전 문장이 이상함 | **오히려 기회다.** 1단계가 증명하려는 게 정확히 그 문제다. 당황하지 말고 정규화 결과를 가리켜라. | 내레이션: "보시는 것처럼 음성인식은 사투리를 놓칩니다. 저희가 푸는 게 이 지점입니다." |
| **전부 실패** | 노트북·프로젝터 문제 | **미리 녹화한 영상 재생.** | 촬영본을 **로컬 파일로** 노트북에 둔다. 클라우드 링크만 믿지 마라. |
