# Voisso 데모 대본 (촬영 · 시연용)

> **목표 길이 2분 55초.** 6단계 + MCP 마무리. (상한 3분을 넘기지 마라)
> 어르신 화면이 **전화 UI + 자막**으로 바뀌었다. 1단계가 두 컷(어르신 모드 → 시연 모드)이 된다.
> 각 단계는 심사 기준 하나씩을 증명한다. 설명하지 말고 **보여준 다음** 한 줄로 못박는다.
>
> **클라이맥스는 5·6단계(담당자 핸드오프 → 진행 안내 콜백)다.** 앞 단계는 거기로 가는 길이다.
> 시간이 모자라면 1~3단계를 깎아라. **5·6단계를 깎지 마라.**
>
> ⚠️ 이 문서의 대본은 **현재 동작하는 기능**만 담았다. 아직 작업 중인 것은 🚧 로 표시했다.
> 촬영 시점에 완성되지 않았다면 그 컷은 빼고 간다. 없는 걸 있는 척하면 심사에서 더 크게 잃는다.
> **지금 🚧 인 것은 5단계(담당자 핸드오프) 하나뿐이다.** 1~4단계와 6단계는 실행해서 확인했다.

## 시간 배분

| 구간 | 길이 | 누적 | 증명하는 심사 기준 |
|---|---|---|---|
| **0. 문제 제기** | 0:00–0:12 | 12초 | (도입 — 여기서 못 잡으면 나머지가 무의미하다) |
| **1. 어르신 화면(전화 UI) → 시연 모드로 뒤집기** | 0:12–0:50 | **38초** | 혁신성 및 차별성 (20%) · 접근성 설계 |
| **2. AI가 사투리로 되물으며 슬롯 채움** | 0:50–1:10 | 20초 | 기술적 완성도 (25%) |
| **3. 통화 종료 → 민원카드 → 사무분장 원문 근거** | 1:10–1:32 | 22초 | 공공데이터 실사용 · 필수 조건 |
| **4. 담당자 대시보드에 실시간 도착** | 1:32–1:43 | 11초 | 공공부문 활용 가능성 (25%) |
| **5. 담당자가 통화를 잇는다 — 사람이 이어받는다** | 1:43–2:15 | **32초** | 공공부문 활용 가능성 · 혁신성 (클라이맥스 1) |
| **6. 시스템이 먼저 전화를 건다 — 진행 안내 콜백** | 2:15–2:43 | **28초** | 혁신성 · 임팩트 (클라이맥스 2) |
| **7. MCP 서버 — 우리 서비스 없이도 쓴다** | 2:43–2:55 | 12초 | 지속가능성 및 임팩트 (20%) |

프로토타입 보너스(10%)는 **영상 전체가 실제 화면**이라는 사실로 증명된다. 슬라이드를 섞지 마라.

**1단계가 38초로 늘어난 이유.** 어르신 화면이 **전화 UI + 자막**으로 바뀌면서, 우리의 핵심
증거인 **전사 3단 대비가 어르신 화면에서 사라졌다.** 없앤 게 아니라 시연 모드로 옮긴 것이라,
1단계는 이제 **어르신 화면(18초) → 시연 모드 전환(20초)** 두 컷으로 간다.
**그 전환 자체가 주장이다** — "어르신에게는 단순하게, 심사위원에게는 전부."
대신 2·3·4단계에서 6초를 덜어 총 길이는 그대로 2분 55초를 지킨다.

**왜 5·6단계에 60초를 몰아주는가.** 1~4단계는 "AI가 민원을 잘 받는다"까지다. 그것만으로는
공공기관이 도입하지 않는다.

- **5단계**가 *"그래서 사람이 어떻게 이어받는가"* 에 답한다. AI 가 멈추고 사람이
  책임지는 경계를 보여주는 자리다.
- **6단계**가 *"그 다음 어르신은 어떻게 아는가"* 에 답한다. 지금 어르신이 진행 상황을 알려면
  **다시 전화해서 ARS 를 또 뚫어야 한다** — 0단계에서 문제로 제기한 그 벽이다.
  방향을 뒤집어 **시스템이 먼저 전화를 걸면** 그 벽이 사라진다. 영상이 처음 던진 질문에
  마지막에 답하는 구조라, 여기서 대본이 닫힌다.

심사위원이 기억할 장면은 이 둘이다. 앞을 3초씩 깎아서라도 지켜라.

## 0. 문제 제기 — 0:00–0:12 ⏱ 12초

**첫 15초가 전부다.** 아키텍처 다이어그램으로 시작하지 마라. 문제를 던지고 곧바로 사투리를 들려준다.

| | |
|---|---|
| **화면** | 검은 배경에 흰 텍스트 두 줄. 그다음 **바로** 통화 화면으로 컷 전환. |
| **자막** | `경상북도, 65세 이상 인구 비율 전국 최상위권` → `민원 창구는 여전히 ARS입니다` |

**내레이션**

> "경북 어르신이 도청에 전화를 겁니다. 1번 도로, 2번 상하수도, 3번… 끝까지 듣고 자기 민원이 몇 번인지 골라야 합니다. 잘못 누르면 처음부터. 그리고 그 다음 안내는, 표준어로만 나옵니다."

**연출 주의**
- 이 15초 동안 Voisso가 무엇인지 **설명하지 않는다.** 문제만 던진다.
- 0:15에 곧바로 어르신 목소리가 나와야 한다. 정적을 두지 마라.

## 1. 어르신 화면은 전화기다 → 시연 모드로 뒤집기 — 0:12–0:50 ⏱ 38초

**증명 대상: 혁신성 및 차별성 (20%) · 접근성 설계**

이 컷은 **두 화면을 연달아** 보여준다. 앞 18초는 어르신이 보는 것, 뒤 20초는 우리가 만든 것.
**그 전환 자체가 이 프로젝트의 주장**이라 컷을 나누지 말고 한 번에 간다.

### 1-A. 어르신 모드 (0:12–0:30, 18초)

| | |
|---|---|
| **화면** | `http://localhost:8000/call/` — **전화 UI.** 통화 상태 · 상대 표시 · 큰 말하기 버튼 |
| **핵심 컷** | 어르신이 말하는 동안 **자막 한두 줄**이 아래로 지나가는 장면 |

```
어르신 발화 :  비가 오면 집앞 도로에 물이 안 빠져가 큰일이라예
화면        :  (자막 한 줄로 지나감. 대화 목록은 쌓이지 않는다)
```

**내레이션**

> "어르신 화면입니다. 큰 버튼 하나와 자막 한 줄. 그게 전부입니다.
> 채팅창이 아니라 **전화기**입니다. 실제 전화에서 어르신은 대화 기록을 읽지 않습니다.
> 듣고, 말할 뿐입니다."

### 1-B. 시연 모드로 전환 (0:30–0:50, 20초)

| | |
|---|---|
| **화면** | 우상단 **「시연」 버튼을 누른다** (또는 주소에 `?debug=1`). 같은 통화, 다른 화면 |
| **핵심 컷** | **전사 3단 대비가 한 화면에 뜨는 순간.** 여기서 1.5초 멈춘다 |

```
받아쓴 원문 :  비가 오면 집앞 도로에 물이 안 빠져가 큰일이라예
어르신의 말 :  비가 오면 집앞 도로에 물이 안 빠져가 큰일이라예
표준어 교정 :  비가 오면 집앞 도로에 물이 안 빠져서 큰일이에요
                                    └ -가 → -서 · -라예 → -이에요
```

**내레이션**

> "그런데 같은 화면을 이렇게 뒤집으면 — 안에서 무슨 일이 일어나는지 보입니다.
> 음성인식은 표준어 기준으로 학습돼 있어서 사투리를 자주 놓칩니다. 그리고
> **받아쓴 문장이 그대로 검색어가 됩니다.** 어긋나면 사무분장 원문과 매칭되지 않고,
> **엉뚱한 과로 배정됩니다.** 그래서 어휘 382개와 어미 규칙 71개로 표준어를 되돌린 다음
> 부서를 찾습니다. **사람이 알아듣게 하려는 게 아니라, 기계가 찾아내게 하려는 겁니다.**"

**못박는 한 줄**

> "어르신이 말을 고치는 게 아니라, 시스템이 맞춥니다.
> **사투리로 말해도 정확한 부서로 갑니다.** 그게 이 레이어가 하는 일입니다."

**연출 주의**
- **전환 순간을 화면에 담아라.** 버튼을 누르는 손과 화면이 바뀌는 장면이 한 컷에 있어야
  "같은 프로그램의 두 얼굴"이 전달된다. 두 개의 다른 화면을 찍은 것처럼 보이면 실패다.
- 1-A 에서 **자막이 지나가는 속도**를 확인하라. 너무 빨리 사라지면 시청자가 못 읽는다.
  필요하면 그 구간만 재생 속도를 늦춰 편집한다(화면 조작이 아니라 편집이므로 정직하다).
- 1-B 의 세 줄에서 **바뀐 부분에 하이라이트**를 넣어라. 지나가면 못 본다.
- 음성 입력이 준비되지 않았다면 **텍스트 입력으로 진행한다.** 문장이 같으면 메시지는 동일하다.
- 🚧 **자막 표시는 P7이 작업 중이다.** 촬영 시점에 자막이 안 뜨면 1-A 를 **전화 UI 자체
  (큰 버튼·통화 상태)만** 보여주고 넘어가라. 1-B 는 그대로 간다 — **전사 3단은 이미 동작한다.**

## 2. AI가 사투리로 되물으며 슬롯을 채움 — 0:50–1:10 ⏱ 20초

**증명 대상: 기술적 완성도 (25%)**

| | |
|---|---|
| **화면** | 통화 화면 우측 슬롯 패널. 4개 항목이 차례로 채워진다. |
| **슬롯** | `무슨 일` · `어디서` · `언제부터` · `연락처` |

**대화 흐름**

```
AI    :  어데신지 여쭤봐도 될까예?          ← 표준어 응답을 경북 사투리로 변환해 출력
어르신:  안동 옥동인데예
AI    :  언제부터 그랬는교?
어르신:  장마 지나고부터 계속 그래예
```

**내레이션**

> "AI는 사투리로 되묻습니다. 무슨 일인지, 어디인지, 언제부터인지, 연락처. 네 가지가 채워지면 통화를 마무리합니다. 한 항목은 최대 두 번까지만 묻고, 그래도 안 나오면 넘어갑니다. 어르신을 심문하지 않기 위해서입니다."

**못박는 한 줄**

> "버튼을 누를 필요가 없습니다. 그냥 말하면 됩니다."

**연출 주의**
- 슬롯이 **하나씩 체크되는 애니메이션**이 이 컷의 시각적 핵심이다. 패널이 화면에 반드시 들어오게 프레이밍하라.
- 되묻는 문장이 사투리로 나온다는 점을 자막으로 강조하라 (`될까요?` → **`될까예?`**).

## 3. 통화 종료 → 민원카드 → 사무분장 원문 근거 — 1:10–1:32 ⏱ 22초

**증명 대상: 공공데이터 실사용 (필수 조건) · 공공부문 활용 가능성**

이 컷이 **이 프로젝트에서 가장 중요하다.** 여기서 공공데이터를 실제로 쓴다는 걸 증명한다.

| | |
|---|---|
| **화면** | 통화 종료 → 민원카드 생성. 카드의 `배정 근거` 인용 블록을 **확대**한다. |

**화면에 뜨는 값** — 아래는 서버에서 실제로 나온 민원카드다 (2026-08-22 실행)

```
요약   : 안동시 옥동, 집앞 도로에 물이 안 빠져서 큰일이에요 (장마철부터)
분류   : 도로·하수 유지관리
긴급도 : 보통 — "위험 신호가 없어 정상 처리 일정으로 분류했습니다" (규칙 판정)
배정   : 기후환경국 맑은물정책과        ← 단독 배정 (1순위 0.711, 2순위와 격차 0.32)
근거   : ◦ 하수도분야 국도비 보조사업 예산 및 추진 ◦ 하수도사업 재원협의 및 총사업비변경
         관련 업무 ◦ 하수도 재난재해대책(호우, 태풍 등) 수립 및 시행 …
대안   : 기후환경국 수자원관리과 (0.369) · 건설도시국 도로철도과 (0.311)
연락처 : 010-****-5678               ← 자릿수를 보존한 채 가운데만 가린다
```

> **긴급도도 같은 원칙이다 — 근거 한 줄이 붙는다.** 이 시나리오는 `보통` 이지만,
> "지금 집에 물이 차오르고 있어예" 였다면 `응급` 으로 판정되고, **접수보다 119가 먼저** 나간다.
> 그런데 **통보가 아니라 질문이다** — *"제가 119에 연결해 드릴까예?"* → "네" → *"예, 119로
> 연결하겠습니더."* 어르신은 버튼보다 말이 편하다는 것이 이 프로젝트의 전제이므로,
> **안전 기능도 같은 원칙을 따른다.**
> 시간이 없으면 카드의 긴급도 배지를 스치기만 하고 내레이션 한 문장으로 넘겨라 —
> **"사람이 위험한 상황은 접수로 끝내지 않습니다. 그리고 통보하지 않고 여쭙습니다."**
> 별도 컷을 만들지 마라(총 길이가 넘친다).

> **확신이 뚜렷하면 단독 배정한다.** 다만 갈리는 민원에서는 단정하지 않는다 —
> "집이 물에 잠겼어요" 는 `확신: False` 와 함께 **안전행정실 자연재난과 / 기후환경국
> 맑은물정책과** 를 나란히 내민다(원인이 재난인지 하수도인지 모르기 때문이다).
> 시간이 되면 이 화면을 0.5초 스쳐라. **"모른다고 말할 수 있다"는 것 자체가 신뢰 요소다.**

**내레이션**

> "통화가 끝나면 민원카드가 만들어집니다. 여기서 중요한 건 맨 아래 '근거' 한 줄입니다. 이건 AI가 지어낸 설명이 아니라, **경상북도청이 공개한 그 부서의 사무분장 원문**입니다. 저희는 도청 조직도에서 96개 부서, 1,866건의 담당업무를 수집해 라우팅 근거로 씁니다."

**못박는 한 줄**

> "AI가 그렇게 판단했다, 로 끝나지 않습니다. 왜 그 부서인지가 공공데이터 원문으로 남습니다."

**연출 주의**
- `근거` 블록을 **화면 가득 확대**하라. 이 한 줄이 심사 기준 두 개(공공데이터 실사용 + 공공부문 활용 가능성)를 동시에 친다.
- 확신도가 낮을 때 **후보를 여러 개 제시**하는 화면이 있다면 0.5초라도 스쳐라. "단정하지 않는다"는 신뢰 요소다.

| | |
|---|---|
| **화면** | 4단계의 **분할 화면을 그대로 유지**한다. 좌: 어르신 통화 화면 / 우: 담당자 대시보드 |

**흐름**

```
④ 담당자가 표준어로 친다 → 어르신은 익숙한 말투로 받는다
⑤ 어르신이 사투리로 답한다 → 원문 그대로 전달되고, 기록에는 표준어도 함께 남는다
```

```
담당자가 친 것   :  기후환경국 맑은물정책과 담당자입니다. 접수 내용 확인했습니다.
어르신이 듣는 것 :  기후환경국 맑은물정책과 담당자입니더. 접수 내용 확인했습니더.

담당자가 친 것   :  그러면 내일 아침에 현장에 나가 보겠습니다. 조금만 기다려 주세요.
어르신이 듣는 것 :  그라믄 내일 아침에 현장에 나가 보겠습니더. 조금만 기다려 주이소.
                    └ 그러면→그라믄 · 주세요→주이소 · -습니다→-습니더

어르신이 말한 것 :  낼 오신다 캅니꺼?
기록에 남는 것   :  낼 오신다 캅니꺼?  /  내일 오신다 합니까?   (원문 + 표준어)
                    └ 담당자는 원문을 그대로 읽는다. 표준어는 **검색·기록용**이다.
```

> **주의 — 이렇게 말하지 마라.** "담당자가 못 알아듣는 사투리를 통역해 준다" 는 **틀린 주장**이다.

> ① 담당자의 글이 어르신에게 **익숙한 말투로** 전달된다(편안함),
> ② 표준어 변환은 **검색과 기록**을 위한 것이다(정확도).

**내레이션**

> "담당자가 '통화 잇기'를 누릅니다. 여기서부터 **AI 는 말하지 않습니다.** 사람이 직접 응대합니다.
> 담당자는 표준어로 치고, 어르신에게는 **익숙한 말투로** 전달됩니다.
> 담당자가 사투리를 못 알아들어서가 아닙니다. 한국 사람은 다 알아듣습니다.
> **어르신이 하던 대로 말하게 두려는 겁니다.** 기계 앞에서 말을 고르던 분이,
> 이제 사람과 편하게 이야기합니다."

**못박는 한 줄** — *이 영상에서 가장 중요한 한 문장이다. 또박또박 읽어라.*

> "AI 에게 전권을 주는 게 아닙니다. **접수까지만 AI 가 돕고, 처리는 사람이 책임집니다.**
> 'AI 가 민원을 처리한다' 는 공공기관이 받아들이지 않습니다. 하지만
> 'AI 가 접수를 돕고 담당자가 처리한다' 는 — 내일부터 쓸 수 있습니다."

**연출 주의**
- **두 화면이 한 프레임에 같이 보여야 의미가 산다.** 한쪽씩 번갈아 잡으면 같은 순간이라는 것이
  전달되지 않는다. 화면 배치는 아래 「촬영 체크리스트 → 3. 화면」의 **5단계 분할 배치**를 따른다.
- 담당자가 타이핑하는 손과 어르신 화면에 사투리가 뜨는 순간을 **끊지 말고 한 컷으로** 잡아라.
  컷을 나누면 "편집으로 만든 것 아니냐"는 의심이 생긴다.
- 변환된 어절(`그라믄` · `주이소` · `캅니꺼`)에 **자막 하이라이트**를 넣어라. 지나가면 못 본다.
- AI 정지 배지("지금부터 담당자가 직접 응대합니더")를 **반드시 화면에 잡아라.** 누가 말하고
  있는지 헷갈리면 그 자체로 신뢰 문제가 된다 (계약서 5-B절).
- 담당자 이름은 **가명**을 쓴다. 실명·실제 연락처가 화면에 잡히면 안 된다.

**동작하지 않을 때의 대체 (우선순위 순)**

1. **한쪽 방향만 동작하면 그쪽만 보여준다.** 담당자→어르신(사투리 출력)이 더 극적이다.
   내레이션에서 반대 방향은 "같은 방식으로 되돌립니다" 로 한 문장만 언급한다.
2. **서버만 되고 UI 가 안 되면** `curl` 로 `POST /api/handoff/{id}/message` 를 보내고
   어르신 화면에 사투리로 뜨는 것만 잡는다. 터미널이 화면에 나오는 건 감점 요인이 아니다.
3. **전부 안 되면 이 컷을 뺀다.** 4단계에서 곧바로 7단계(MCP)로 간다. 총 길이는 **2분 23초**가
   되고, 그래도 완결된 대본이다. 3단계(민원카드 근거)에 5초를 더 주면 **2분 28초**다.
   **내레이션에서 핸드오프를 언급조차 하지 마라.** 로드맵으로 말하고 싶으면
   영상이 아니라 제출문에서 말한다.

```
③ 받으면 AI 가 담당자의 글을 사투리로 읽어 준다
④ 어르신이 추가로 물으면 → 받아 적어 담당자에게 전달한다 (AI 가 답하지 않는다)
```

### 🔴 0. 지금 음성이 꺼져 있다 — 촬영 전에 반드시 처리하라

**타입캐스트 사용량 한도를 초과해 `VOISSO_TTS_PROVIDER=none` 으로 내려둔 상태다.**
이대로 찍으면 **영상 전체에 어르신이 듣는 목소리가 없다.** 대본의 1·2·5·6단계가
전부 "글자만 오가는 화면"이 된다. 다른 어떤 항목보다 먼저 처리한다.

- [ ] **타입캐스트 계정 교체 또는 한도 복구.** 새 키를 `.env` 의 `TYPECAST_API_KEY` 에 넣고
      `VOISSO_TTS_PROVIDER=typecast` 로 되돌린다.
- [ ] **음성이 실제로 나오는지 확인한다.** 서버를 재기동한 뒤:
      ```bash
      curl -s localhost:8000/api/health | python3 -m json.tool | grep -A3 '"tts"'
      ```
      `"provider": "typecast"` 이고 `"audio": true` 여야 한다. `"none"` 이면 아직 안 된 것이다.
- [ ] **한 문장 합성해 귀로 들어본다 — 촬영 직전 딱 한 번.**
      한도가 남아 있어도 보이스 ID 가 틀리면 소리가 안 난다.
      ⚠️ **개발 중에는 이 명령을 돌리지 마라** (계약서 5-D). 크레딧은 촬영용이다.
      ```bash
      curl -s -X POST localhost:8000/api/tts/stream \
           -H 'Content-Type: application/json' \
           -d '{"text":"접수해 드리겠습니더"}' --output /tmp/voisso-check.wav
      afplay /tmp/voisso-check.wav      # macOS
      ```
- [ ] **이 확인이 끝나면 다시 `none` 으로 돌려놓는다.** 촬영 전까지 개발·테스트가
      이어지므로, 켜 둔 채로 두면 다음 테스트가 크레딧을 먹는다.
- [ ] **끝내 복구가 안 되면 — 텍스트 모드로 찍는다.** 대본의 메시지는 하나도 잃지 않는다
      (사투리 *텍스트* 변환이 우리 주장이고, 억양은 원래 미검증이라고 밝혀 왔다).
      다만 내레이션에서 **"사투리로 들려드립니다"를 "사투리로 보여드립니다"로 바꿔라.**
      그리고 **1단계에서 음성 입력 대신 텍스트 입력을 쓴다.**

### ⚡ 원터치 실행

```bash
./scripts/demo.sh                # 데이터 준비 → 서버 기동 → 브라우저 열기
./scripts/demo.sh --no-browser   # 브라우저를 직접 배치하고 싶을 때
./scripts/test.sh                # 지금 무엇이 동작하는지 한눈에 (없는 키는 SKIP)
```

**둘 다 완성되어 동작한다.** `demo.sh` 는 7단계를 밟으며 무엇을 하는지 출력하고,
실패하면 다음에 무엇을 하면 되는지 알려주고 멈춘다. 아래 수동 절차는 **이 스크립트가
실패했을 때 어디를 봐야 하는지** 알기 위한 것이다.

### 1. 데이터 · 서버

- [ ] **데이터 존재 확인** — 없으면 라우팅이 전부 실패한다. 가장 먼저 본다.
  ```bash
  python3 -c "from voisso.data import load_departments as f; d=f(); print('부서', len(d['departments']), '| 수집', d['meta']['fetched_at'])"
  ```
  없으면 → `python3 scripts/scrape_gb_departments.py` (약 35초, 네트워크 필요)
- [ ] **라우팅 동작 확인** — 데모에 쓸 그 문장으로 미리 돌려본다.
  ```bash
  python3 -c "from voisso.routing import route; r=route('비가 오면 집앞 도로에 물이 안 빠져가 큰일이라예'); print(r['matches'][0]['full_name'], '|', r['matches'][0]['evidence'])"
  ```
- [ ] **MCP 셀프테스트 통과** — `python3 -m mcp_server.selftest`
      마지막 줄이 `N/N 통과` 여야 한다. **실패 항목이 있으면 그 화면은 찍지 마라.**
      대신 Claude Desktop 실사용 컷으로 5단계를 대체한다.
- [ ] **API 서버 기동** — `pip install -r requirements.txt` 후 `python3 -m server`.
      상태 확인은 헬스체크 한 줄이면 된다. `degraded: true` 면 무엇이 빠졌는지 `missing_keys` 가 알려준다.
      ```bash
      curl -s localhost:8000/api/health | python3 -m json.tool
      ```
- [ ] **통합 리허설 1회** — `python3 scripts/rehearsal.py --runs 3` 이 서버 기동부터
      민원카드·대시보드 반영까지 브라우저 없이 3회 재현하고 `docs/REHEARSAL.md` 에 기록한다.
      **여기서 실패하면 촬영을 시작하지 마라.**
- [ ] **전화번호 매핑 확인** — `data/private/phone_map.json` 이 있으면 실번호, 없으면 대표번호
      `1522-0120` 로 표시된다. **영상에 실제 공무원 번호가 잡히지 않게** 할 거면 일부러 비워도 된다.
- [ ] 🚧 **담당자 핸드오프 동작 확인 (5단계)** — 작업 중인 기능이다. 촬영 직전에 반드시 찍어본다.
      민원카드 하나를 만든 뒤 `complaint_id` 를 넣고 아래를 돌려서, **네 줄이 다 나오면** 촬영 가능이다.
      하나라도 실패하면 5단계 절의 「동작하지 않을 때의 대체」로 간다.
      ```bash
      CID=0001   # 방금 만든 민원카드 번호
      curl -s -X POST localhost:8000/api/handoff/$CID/start \
           -H 'Content-Type: application/json' \
           -d '{"officer_name":"홍길동","department":"기후환경국 맑은물정책과"}'
      curl -s -X POST localhost:8000/api/handoff/$CID/message \
           -H 'Content-Type: application/json' \
           -d '{"role":"officer","text":"그러면 내일 아침에 현장에 나가 보겠습니다. 조금만 기다려 주세요."}'
      curl -s localhost:8000/api/handoff/$CID | python3 -m json.tool
      ```
      마지막 응답의 메시지에 `dialect` 와 `standard` 가 **둘 다** 있고, `dialect` 쪽이
      `그라믄 … 주이소` 로 바뀌어 있어야 한다. 이게 5단계 화면의 실체다.
- [ ] **양쪽 방향이 되는지 확인** — 위에서 `"role":"caller","text":"낼 오신다 캅니꺼?"` 를 보내고
      `standard` 가 `내일 오신다 합니까?` 로 오는지 본다. 한쪽 방향만 되면 대체안 1번으로 간다.
- [ ] 🖐 **화면에서 직접 눌러 본다 (`curl` 로는 확인되지 않는 부분).**
      서버 API 는 검증했지만 **버튼·화면 전환은 브라우저에서만 확인된다.**
      `/demo` 를 열고 아래 네 가지를 손으로 밟아라. 하나라도 막히면 그 단계의 대체안으로 간다.
      1. 대시보드에서 **[통화 잇기]** → 어르신 화면에 "담당자가 직접 응대합니더" 가 뜨는가
      2. 담당자가 친 문장이 **어르신 화면에 사투리로** 나타나는가
      3. 대시보드에서 진행 상황을 쓰고 **[안내 전화 걸기]** → 어르신 화면에 **수신 전화**가 뜨는가
      4. **받기** 버튼을 누르면 브리핑이 재생/표시되는가
- [ ] **진행 안내 콜백 확인 (6단계)** — 같은 `complaint_id` 로 아래를 돌린다.
      ```bash
      curl -s -X POST localhost:8000/api/callback/$CID/schedule \
           -H 'Content-Type: application/json' \
           -d '{"briefing":"현장 확인 완료했습니다. 이번 주 내로 배수관 준설 예정입니다.","officer_name":"홍길동","department":"기후환경국 맑은물정책과"}'
      curl -s -X POST localhost:8000/api/callback/$CID/answer -d '{}' -H 'Content-Type: application/json'
      curl -s -X POST localhost:8000/api/callback/$CID/message \
           -H 'Content-Type: application/json' -d '{"role":"caller","text":"그라믄 언제 옵니꺼?"}'
      curl -s localhost:8000/api/callback/$CID | python3 -m json.tool
      ```
      **두 가지를 확인한다.** ① `briefing` 에 `standard` 와 `dialect` 가 둘 다 있는가.
      ② "언제 옵니꺼?" 에 대한 AI 응답이 **일정을 지어내지 않고** "담당자에게 여쭤보고 다시
      연락드리겠습니더" 로 오는가. **②가 깨지면 6단계를 찍지 마라** — AI 가 행정 약속을
      만드는 장면이 영상에 남는 것이 최악이다.

### 2. 브라우저 · 마이크

- [ ] **Chrome 사용** (필수). 통화 UI는 `getUserMedia` + `MediaRecorder` 로 마이크를 잡는다.
      Safari는 코덱·권한 동작이 달라 당일 변수를 만든다.
- [ ] **`file://` 로 열지 마라.** 마이크는 보안 컨텍스트를 요구한다. 반드시 로컬 서버로 연다.
  ```bash
  python3 -m server                # 통화 UI·대시보드·발표 화면·API 를 한 프로세스가 서빙한다
  # → http://localhost:8000/call/        (1~3단계는 이 주소)
  # → http://localhost:8000/demo/        (4~6단계는 이 분할 화면)
  # → http://localhost:8000/dashboard/   (대시보드 단독으로 볼 때)
  ```
  **촬영용 서버는 기본 데이터 디렉터리(`./data`)를 그대로 쓴다.** 발표용 민원카드가
  거기 있기 때문이다. 반대로 **개발·테스트 서버는 절대 여기에 붙이지 마라** —
  테스트로 만든 카드가 발표 화면에 섞인다 (계약서 5-E, 아래 참조).
  API 서버 없이 목 모드만 보여줄 거라면 정적 서버로도 열린다
  (`python3 -m http.server 8080` → `http://localhost:8080/web/call/?mock=1`).
  **다만 촬영 주소를 둘로 섞지 마라.** 서버가 살아 있는 한 `:8000/call/` 하나로 간다.
- [ ] **마이크 권한 미리 허용** — 촬영 중 권한 팝업이 뜨면 그 컷은 버린다. 사전에 한 번 눌러 둔다.
- [ ] **입력 장치 확인** — 시스템 설정에서 사용할 마이크가 선택돼 있는지. 외장 마이크 권장.
- [ ] **알림 끄기** — macOS 방해금지 모드. 슬랙·메일 배너가 뜨면 다시 찍어야 한다.

### 3. 화면

- [ ] **해상도 1920×1080 고정.** 심사 영상은 대개 축소 재생된다. 그 이상은 글씨가 작아진다.
- [ ] **테마: 라이트 모드로 통일한다.**
      통화 UI와 대시보드 **둘 다 `prefers-color-scheme` 자동 전환**을 지원한다.
      시스템 테마가 바뀌면 두 화면 톤이 어긋난다. **촬영 전 시스템을 라이트로 고정**하라.
      (어두운 배경을 원하면 둘 다 다크로 — **섞지만 않으면 된다.**)
- [ ] **브라우저 확대 125~150%** — 어르신 대상 서비스인데 글씨가 작으면 설득력이 떨어진다.
      단 `/demo` 분할 화면에서는 **100~110%** 로 낮춰라. 우측 담당자 화면의 입력창이 접힌다.
- [ ] **북마크바·확장프로그램 아이콘 숨기기.** 전체화면(⌃⌘F) 권장.
- [ ] **개인정보 점검** — 화면에 실제 전화번호, 개인 계정, 사내 URL이 잡히지 않는지 **녹화 전 한 번 훑는다.**

#### 4~6단계 화면 배치 — `/demo` 를 쓴다

5·6단계는 **두 화면에서 동시에 벌어지는 일**이 핵심이라, 한 프레임에 둘이 같이 들어와야
한다. 번갈아 잡으면 "사람이 이어받는다"도 "시스템이 먼저 건다"도 전달되지 않는다.

**창 두 개를 손으로 배치하지 마라. 발표용 화면이 따로 있다.**

```
http://localhost:8000/demo/
```

```
┌───────────────────────────────────────────────────────────┐
│ ① 접수  ② 배정  ③ 민원카드  ④ 대시보드  ⑤ 담당자 연결  ⑥ 진행 안내 │  ← 단계 표시
│                                        [ 담당자 연결 ]        │
├──────────────────┬────────────────────────────────────────┤
│  좌 35%          │  우 65%                                 │
│  어르신 화면      │  담당자 화면                             │
│  (전화 UI + 자막) │  (민원카드 · 응대 입력 · 진행 상황 작성)    │
└──────────────────┴────────────────────────────────────────┘
```

- [ ] **`/demo` 로 연다.** 좌우 비율(기본 35:65)은 경계선을 끌어 조절한다. 어르신 화면은
      전화 UI라 좁아도 되고, 담당자 화면은 카드와 입력창이 함께 보여야 하므로 넓게 준다.
- [ ] **상단 단계 표시를 활용하라.** 지금 몇 단계인지가 화면에 늘 떠 있어 시청자가
      길을 잃지 않는다. 컷을 넘길 때 해당 단계를 눌러 두면 편집 없이도 흐름이 보인다.
- [ ] **혼자 찍으면 「담당자 연결」 버튼을 쓴다.** 대시보드를 따로 조작하지 않아도
      ⑤·⑥ 단계가 흐른다. 손이 두 화면을 오가는 컷이 사라져 훨씬 깔끔하다.
- [ ] **테마를 라이트로 고정.** 두 화면이 한 프레임에 있으므로 톤이 어긋나면 바로 티가 난다
      (둘 다 `prefers-color-scheme` 자동 전환을 지원한다).
- [ ] **대시보드는 상세 패널을 연 채로 대기.** ⑤에서 [통화 잇기] 까지 클릭 수를 줄인다.
- [ ] **전환 시점을 정해 둔다.** 1~3단계는 **통화 화면 단독(전체화면)**, 3단계에서 민원카드가
      뜨는 순간 `/demo` 분할로 넘어가 **4·5·6단계를 끊지 않고** 간다.
- [ ] **6단계에서 시선이 좌측으로 넘어간다.** 담당자가 쓰고(우) → 어르신에게 전화가 온다(좌).
      수신 벨이 뜰 때 커서를 좌측으로 옮겨 시선을 유도하라.
- [ ] **커서를 크게.** 접근성 설정에서 포인터 크기를 키우면 어느 화면을 조작 중인지
      시청자가 따라올 수 있다.

#### 1단계 모드 전환 리허설 (새로 생긴 컷)

- [ ] **어르신 모드 → 시연 모드 전환을 미리 손에 익혀라.** 우상단 「시연」 버튼 한 번이다.
      촬영 중 주소창을 고쳐 `?debug=1` 을 치면 페이지가 새로 뜨면서 **통화가 끊긴다.**
      반드시 **버튼**으로 전환하라.
- [ ] **전환 후 전사 3단이 실제로 뜨는지 확인한다.** 통화를 한 턴 진행한 뒤 시연 모드로
      바꿔서, 받아쓴 원문 · 어르신의 말 · 표준어 교정 세 줄이 보이는지 눈으로 본다.
- [ ] **모드 선택은 `localStorage` 에 남는다.** 앞 테이크에서 시연 모드로 끝냈으면 다음
      테이크가 시연 모드로 시작한다. **1-A 를 찍기 전에 어르신 모드인지 반드시 확인하라.**

## 실패 대비책

**목적: 발표장에서 당황하지 않는 것.** 각 상황의 폴백을 미리 정해 두고, 전환에 10초 이상 쓰지 않는다.

| 상황 | 증상 | 폴백 | 전환 방법 |
|---|---|---|---|
| **네트워크 끊김** | 통화 턴마다 화면이 멈춘 것처럼 보임 | **폴백 조합으로 재기동.** 라우팅과 MCP는 네트워크가 필요 없다 — 전부 로컬에서 돈다. | ⚠️ **아무것도 안 하면 안 된다.** 키가 `.env` 에 살아 있으면 STT 60초 + LLM 45초 + TTS 30초를 **매 턴 기다린다**(실측, `docs/FALLBACK_REPORT.md` 3b). 아래 한 줄로 서버를 다시 띄워라. 턴당 응답이 밀리초로 떨어진다. <br>`env VOISSO_AGENT_PROVIDER=rule VOISSO_STT_PROVIDER=none VOISSO_TTS_PROVIDER=none python3 -m server` <br>그리고 **당일 `--refresh` 를 돌리지 마라.** 있는 데이터로 간다. |
| **API 서버 다운** | 통화 화면이 "서버 응답 없음" | **목 모드로 즉시 전환.** 전 과정이 그대로 시연된다. | 서버가 아직 살아 있으면 주소 끝에 `?mock=1` → `http://localhost:8000/call/?mock=1`. <br>**서버가 죽었으면 그 페이지 자체를 못 받는다.** 그때는 파일을 직접 연다 → `open web/call/index.html` (`file://` 는 자동으로 목 모드다). 마이크는 안 되므로 **텍스트 입력으로 진행**한다. |
| **마이크 불통 / 권한 거부** | 녹음 버튼이 안 먹음 | **텍스트 입력 모드.** 같은 문장을 타이핑한다. 정규화·라우팅·민원카드는 동일하게 동작한다. | 화면 하단 텍스트 입력창 사용. 내레이션에서 "음성 대신 텍스트로 보여드리겠습니다" 한마디만 넣는다. |
| 🔴 **음성이 안 나옴 (타입캐스트 한도)** | 응답이 글자로만 뜸 | **텍스트 모드로 찍는다.** `VOISSO_TTS_PROVIDER=none` 이면 화면에 텍스트만 뜬다. 대본의 메시지는 하나도 안 잃는다. | 체크리스트 「0. 지금 음성이 꺼져 있다」를 먼저 시도한다. 안 되면 내레이션의 "들려드립니다"를 **"보여드립니다"**로 바꾼다. **접두사는 `VOISSO_` 다** — `VOISO_` 로 쓰면 아무 효과가 없다. |
| 🚧 **자막이 안 뜸 (P7 작업 중)** | 어르신 화면에 오간 말이 안 보임 | **1-A 를 전화 UI 자체만 보여주고 넘어간다.** 1-B(시연 모드 전사 3단)는 그대로 간다 — **핵심 증거는 거기 있다.** | 내레이션에서 "자막 한 줄"을 빼고 "큰 버튼 하나, 그게 전부입니다"로 줄인다. 1-A 를 3~4초 줄이고 1-B 에 얹는다. |
| **시연 모드로 시작해 버림** | 1-A 인데 진단 정보가 보임 | **테이크를 다시 간다.** | 모드는 `localStorage` 에 남는다. 앞 테이크가 시연 모드로 끝났으면 다음이 시연 모드로 시작한다. **1-A 전에 어르신 모드인지 확인하라.** |
| **핸드오프 화면 미완성** | [통화 잇기] 가 없거나 눌러도 반응 없음 | **5단계를 `curl` 시연으로 대체하거나 뺀다.** | 5단계 절의 「동작하지 않을 때의 대체」 3단계를 순서대로. 한쪽 방향만 살아 있으면 담당자→어르신(사투리 출력)만 보여준다. |
| **콜백 화면 미완성** | 수신 전화가 안 뜸 | **6단계를 `curl` 시연으로 대체하거나 뺀다.** 5단계 → 7단계(MCP)로 가면 2분 27초. | 6단계 절의 「동작하지 않을 때의 대체」 참조. **로드맵으로 얼버무리지 말고 아예 언급하지 마라.** |
| ⚠️ **AI 가 일정을 지어냄** | "언제 옵니꺼?"에 AI 가 날짜를 답함 | **6단계를 통째로 뺀다.** | 이건 대체안이 없다. 행정 약속을 만드는 장면은 영상에 남기면 안 된다. 촬영 전 체크리스트에서 미리 잡는다. |
| **STT가 엉뚱하게 받아씀** | 정규화 전 문장이 이상함 | **오히려 기회다.** 1단계가 증명하려는 게 정확히 그 문제다. 당황하지 말고 정규화 결과를 가리켜라. | 내레이션: "보시는 것처럼 음성인식은 사투리를 놓칩니다. 저희가 푸는 게 이 지점입니다." |
| **전부 실패** | 노트북·프로젝터 문제 | **미리 녹화한 영상 재생.** | 촬영본을 **로컬 파일로** 노트북에 둔다. 클라우드 링크만 믿지 마라. |
