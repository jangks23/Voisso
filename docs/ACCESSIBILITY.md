# 접근성 측정 보고서

**대상** `web/call/` (통화 UI, P7) · `web/dashboard/` (담당자 대시보드, P8)
**기준** WCAG 2.1 AA — 다만 우리 사용자는 고령자다. **본문은 AAA(7:1)를 목표로 잡았다.**
**측정일** 2026-08-22 · **측정자** P7
**측정 방식** 실제 브라우저(Chrome 151, 헤드리스)에서 렌더링된 DOM을 훑어
`getComputedStyle` 로 실제 색·크기를 읽고 **WCAG 2.1 상대휘도 공식으로 직접 계산**했다.
외부 접근성 라이브러리를 쓰지 않았다. 배경은 조상 요소를 거슬러 올라가 합성했고,
`opacity` 가 걸린 텍스트는 **합성 후의 실제 색**으로 계산했다(이 처리를 안 하면 실제보다 좋게 나온다).

측정 상태: 대기 화면 / 통화 중 / 민원카드 × 라이트·다크 = 6가지. 아래 값은 그중 **최악값**이다.

## 0. 화면이 두 모드로 나뉘었다 (2026-08-22 재설계)

우리가 없애려는 복잡성을 우리가 재현하게 된다. 그래서 **모드를 나눴다. 기능은 지우지 않고 숨긴다.**

## 4. 글자 크기

| 항목 | 초기 | 1차 조치 | 모드 분리 후 (어르신 모드) |
|---|---|---|---|
| 기본 본문 (`--base`) | 16px | 18px | **20px** |
| 말풍선 발화 | 18.2px | 20.5px | **25px** |
| 입력창 | 16.8px | 18.9px | 20px |
| "말하기" 버튼 글자 | — | — | **26px** |
| "전화 걸기" 버튼 글자 | — | — | **32px** |

어르신 모드에서는 글자 크기 조절 버튼을 **숨겼다.** 기본값이 이미 크기 때문이고,
버튼이 하나라도 줄어드는 편이 낫기 때문이다. 조절 기능 자체는 시연 모드에 남아 있다.

조절 버튼이 있어도 **기본값이 작으면 조절할 줄 모르는 사람은 계속 작게 본다.** 그래서 기본값을 올렸다.
올린 뒤 6개 화면 모두에서 가로 넘침이 없는지 확인했다(`scrollWidth` 520 = `innerWidth` 520).

## 5. 키보드 (WCAG 2.1.1, 2.4.7)

- 통화 화면 기준 **포커스 가능한 요소 14개, 전부 Tab 으로 도달**한다.
  순서: 글자 크기 → 밝기 → (말풍선 토글들) → 예시 칩 → 마이크 → 입력창 → 보내기 → 통화 종료.
- 양수 `tabindex` 를 쓰지 않는다. 화면 전환은 `visibility:hidden` 이라
  **숨겨진 화면의 버튼은 포커스 순서에서 빠진다**(대기 3개 / 통화 14개 / 결과 3개로 실측 확인).
- 포커스 표시: 전역 `:focus-visible` 에 3px 아웃라인(브랜드색) + 오프셋 2px.
  스위치는 시각적 트랙에 아웃라인이 뜨도록 `.switch input:focus-visible + .switch-track` 로 연결했다.
- **조치**: 입력창에 `outline: none` 이 있었다(테두리 색만 바뀜). 제거했다.
  현재 `web/call` 에는 `outline: none` 규칙이 **하나도 없다**(실측 확인).

## 6. 스크린리더 (WCAG 4.1.2, 4.1.3)

- `lang="ko"`, 문서 제목 지정.
- **접근 가능한 이름이 없는 포커스 요소 0개** — 아이콘 버튼은 전부 `aria-label`.
- 라이브 영역:

  | 영역 | 방식 | 안내 내용 |
  |---|---|---|
  | 말풍선 목록 `#transcript` | `aria-live="polite"` | 새 발화·응답 |
  | 통화 상태 `#callStatus` | `role="status"` | 연결 중 → 통화 중 → 통화 종료 |
  | 슬롯 패널 `#slots` | `aria-live="polite"` | 무슨 일/어디서/언제부터/연락처가 채워질 때 |
  | 접수 결과 `#delivery` | `role="status"` | "담당자에게 전달됨" |
  | 통화 시간 `#callTimer` | `aria-live="off"` + 숨김 라벨 | 초마다 읽어대지 않도록 **의도적으로 끔** |

- 음성인식 **중간 결과 말풍선은 `aria-hidden="true"`** 로 두고, 확정된 뒤에 해제한다.
  안 그러면 글자가 바뀔 때마다 스크린리더가 계속 읽는다.
- 장식용 SVG 아이콘은 전부 `aria-hidden="true"`(실측 누락 0건).

## 7. 동작 축소 (WCAG 2.3.3)

`@media (prefers-reduced-motion: reduce)` 에서 모든 애니메이션·전환을 0.01ms 로 줄이고
말풍선 자동 스크롤도 즉시 이동으로 바꾼다. 실측에서 규칙 존재를 확인했다.

## 9. 이 측정이 다루지 못한 것

정직하게 적는다.

- **실제 스크린리더(VoiceOver / NVDA)로 듣지 않았다.** 마크업 상의 이름·역할·라이브 영역이
  올바른지 정적으로 확인했을 뿐이다. 읽는 순서와 어감은 사람이 들어봐야 한다.
- **실제 고령 사용자 테스트를 하지 않았다.** 18px·44px 는 표준 기준이지 사용성 검증이 아니다.
- 색각 이상 시뮬레이션은 하지 않았다. 다만 상태를 색으로만 구분하는 곳은 없다
  (슬롯 = 테두리+굵기+색, 배정 = 라벨 텍스트). 정보는 모두 텍스트로도 제공된다.
- 확대(200%) 와 `prefers-contrast: more` 는 측정하지 않았다.

## 10. 재현 방법

측정 스크립트는 렌더링된 DOM을 읽는 방식이라 어느 페이지에나 붙일 수 있다.
데모 산출물이 아니라 `web/call/` 에 넣지 않았다. 재측정이 필요하면 P7에게 요청하면 된다 —
Chrome 헤드리스로 6개 화면을 열어 위 표를 다시 뽑는 데 2분이면 된다.
