# Voisso 통화 데모 UI (`web/call/`)

경북 어르신이 사투리로 민원을 말하면, AI가 대화로 정보를 모아 담당 부서로 넘기는 과정을
한 화면에서 보여주는 데모다. **빌드 스텝 없음. 의존성 없음. 파일을 열면 바로 뜬다.**

## 여는 법

> ⚠ **개발·테스트로 서버를 띄울 때는 음성을 끈다** (계약 5-D).
> 타입캐스트는 종량제이고, 그 크레딧은 발표·촬영용이다.
>
> ```bash
> VOISSO_TTS_PROVIDER=none python3 -m server --port 8024   # 각자 전용 포트
> ```
>
> `.env` 의 `VOISSO_TTS_PROVIDER=typecast` 는 **사용자 미리보기(8111)와 촬영 전용**이다.
> 통화 UI 자체는 TTS 를 호출하지 않는다 — 서버 응답의 `audio_b64` 를 재생만 한다.
> 음성 없이 뜨면 텍스트만 나오고 나머지는 전부 그대로 동작한다.

```bash
# 1) 가장 간단 — 파일을 그대로 연다 (목 API로 전 과정 시연 가능, 음성 호출 0)
open web/call/index.html            # macOS

# 2) 음성 입력까지 쓰려면 로컬 서버로 연다 (권장)
python3 -m http.server 8080         # 저장소 루트에서
# → http://localhost:8080/web/call/

# 3) 서버(P6)가 떠 있으면 서버가 직접 서빙한다
python3 -m server                   # → http://localhost:8000/call
```

브라우저 음성인식·마이크는 보안 컨텍스트를 요구한다. `file://` 에서 막히면 2번이나 3번으로 열어라.
**음성이 안 되는 환경에서도 텍스트 입력만으로 전 과정이 동작한다.**

## 배포할 때 — 자산 버전을 올려라 (중요)

통화 UI 는 빌드 스텝이 없어 파일명이 늘 같다(`app.js`, `config.js` …).
브라우저가 옛 파일을 캐시하고 있으면 **서버 코드를 아무리 고쳐도 화면이 그대로다.**
실제로 준비 중에 옛 `config.js` 때문에 API 주소가 반영되지 않아 네 번 막힌 사고가 있었다.

```bash
python3 web/call/tools/bump_version.py     # index.html·stt-check.html 의 ?v= 를 한꺼번에 올린다
```

방어는 두 겹이다.

| 층 | 무엇을 막나 | 담당 |
|---|---|---|
| 서버 `Cache-Control: no-store` | 새로 접속하는 브라우저 | `server/` (P6) |
| 태그의 `?v=N` | **이미 옛 파일을 캐시해 둔 브라우저** — 헤더가 붙기 전에 받아간 경우 | 이 디렉터리 |

자산(js/css)을 고쳤으면 커밋 전에 위 명령을 한 번 돌려라. 현재 버전은 `index.html` 상단
`<!-- ASSET_VERSION = N -->` 에 있고, 화면 진단 로그에도 함께 찍힌다.

## 막혔을 때 어디를 보나

페이지를 열면 콘솔에 상태가 한 줄 찍힌다. 개발자도구만 열면 즉시 알 수 있다.

```
[Voisso] API base = http://127.0.0.1:8024 · mode = server · STT = web · assets v5 · page = http://127.0.0.1:8024
```

연결에 실패하면 화면에도 **시도한 주소와 페이지 주소를 함께** 보여준다.
둘이 다르면 캐시 문제이므로 강제 새로고침(⌘⇧R)을 안내한다.

```
http://localhost:8000 에 연결하지 못했습니더.
지금 페이지는 http://127.0.0.1:8111 에서 열렸습니더.
주소가 다르면 브라우저 캐시를 비워 보이소 (⌘⇧R / Ctrl+Shift+R).
```

## 목 / 실서버 전환

`config.js` 의 `USE_MOCK` 한 줄이다. 기본값 `'auto'` 는 다음과 같이 판단한다.

| 여는 방법 | 동작 |
|---|---|
| `file://` 로 열기 | **목 API** — 서버 없이 전 과정 시연 |
| `http(s)://` 로 열기 | **실서버** (`API_BASE`, 기본 `http://localhost:8000`) |

URL 로도 바꾼다. `?mock=0` 실서버 / `?mock=1` 목 / `?api=http://호스트:포트` 주소 지정.
**`?mock=1` 은 데모 당일 서버·네트워크가 죽었을 때의 탈출구다.**
대기 화면 하단에 현재 모드와 음성 입력 경로가 표시된다.

## 음성 입력 — 서버 STT 고정, 아래로 폴백

`config.js` 의 `STT_MODE: 'server'` 가 기본이다. `?stt=web|text` 로 통화 전에 바꿀 수 있고,
시연 모드에서는 경로 칩을 눌러 순환한다. **한 통화 안에서는 경로가 바뀌지 않는다** — 통화 시작
시점에 한 번 정해 끝까지 유지하고, 중간 변경은 실패했을 때만, 이유를 화면에 적으면서 일어난다.

| 순위 | 경로 | 조건 | 비고 |
|---|---|---|---|
| 1 | **서버 STT** (MediaRecorder → `audio_b64`) | 기본값. 서버가 `VOISSO_STT_PROVIDER=openai` | 사투리 어미를 그대로 받아쓴다. 중간 결과는 없다 |
| 2 | **브라우저 내장 음성인식** (Web Speech) | MediaRecorder 미지원이거나 서버 STT 가 꺼진 서버, 또는 `?stt=web` | 중간 결과는 실시간이지만 표준어로 적힌다 |
| 3 | **텍스트 입력** | 항상 | Safari·Firefox 등 최종 폴백 |

서버 STT 는 발화가 끝나야 받아쓰므로 중간 결과가 원리적으로 없다. 대신 **단계가 바뀌는 것**을
보여준다 — `말씀하시는 중…`(시연 모드 말풍선은 경과 초까지) → `받아쓰는 중입니더` → 받아쓴 글.
0.7초 미만의 녹음은 보내지 않고 다시 말씀해 달라고 한다(잘못 눌린 것이고, STT 호출도 낭비된다).

경로 칩에 뜨는 설명은 `/api/health` 가 알려준 실제 모델명을 그대로 쓴다
(예: `서버 음성인식 · 음성 인식 켜짐 (gpt-4o-transcribe)`). 표시와 실제가 어긋나면 안 된다.

미지원 브라우저에서도 **마이크 버튼을 숨기지 않는다.** 누르면 왜 음성이 안 되는지 그 이유를
그대로 안내한다. 마이크 권한은 **통화 버튼을 누른 시점**에 한 번 요청한다(페이지 로드 시에는
요청하지 않는다). 첫 마이크 누름에서 권한창이 뜨면 그 통화의 첫 턴만 다르게 돌기 때문이다.

어르신 통화에 맞춘 조정:

- `continuous = true` — 천천히 말하다 잠깐 쉬어도 인식이 끊기지 않는다.
- 무음 `SPEECH_SILENCE_MS`(기본 1800ms)가 지나면 한 턴이 끝난 것으로 보고 전송한다.
- 엔진이 혼자 끝나면 통화 중인 동안 자동으로 다시 켠다(최대 5회).
- 실패 원인별로 다른 안내를 한다. 특히 `not-allowed` 는 **푸는 방법**(자물쇠 → 마이크 → 허용 → 새로고침)을 알려준다.

## 후보 재점수화 — 방언 사전으로 STT 고르기

Web Speech 는 표준어 기준이라 사투리를 표준어처럼 받아쓴다. 그래서 **후보를 4개 받아
(`maxAlternatives`), 우리 방언 사전에 가장 잘 맞는 후보를 고른다.**

점수 = 사투리 표제어 매칭 ×2.0 + 사투리 어미 ×1.0 + 민원 도메인 어휘 ×1.5 + 경북 지명 ×1.5
+ STT 신뢰도 ×1.0 − 후보 순번 ×0.35

마지막 항이 **1순위 편향**이다. 사전 신호가 뚜렷할 때만 순위를 뒤집고, 근거가 없으면 1순위를 그대로 쓴다.
선택 근거는 통화 중 브라우저 콘솔에 `console.table` 로 남는다(데모 중에도 열어서 보여줄 수 있다).

**검증한 것 / 검증하지 못한 것 — 그대로 적는다.**

- 검증함: P5 가 만든 (사투리 원문, STT 예측) 10쌍을 후보로 넣었을 때 **8쌍에서 사투리에 충실한
  후보를 골랐다.** 나머지 2쌍은 두 후보가 띄어쓰기만 다른 같은 문장이라 1순위 유지가 맞다.
- 검증 못 함: **실제 Chrome 이 돌려주는 후보 목록에 더 나은 후보가 들어 있는지는 측정하지 않았다.**
  마이크로 사람이 말해야만 알 수 있다. 아래 `stt-check.html` 이 그걸 3분 안에 측정하는 페이지다.
  측정 결과 재점수화가 아무것도 바꾸지 못하면, `config.js` 의 `RESCORE_WITH_DIALECT: false` 로 끄고
  데모에서 그 주장을 빼라.

## 실측 페이지 — `stt-check.html`

```
http://localhost:8080/web/call/stt-check.html
```

P5 의 데모 대사 10줄을 하나씩 읽으면, **실제 STT 후보 4개와 점수, 재점수화가 1순위를 바꿨는지**를
보여주고, 마지막에 붙여넣기용 표를 만들어 준다.
P5 의 `DEMO_LINES` 세 번째 값(STT 예측)은 **추측**이므로, 여기서 나온 실측값으로 갈아끼워야 한다.

## 화면 구성

1. **대기** — 큰 통화 버튼 → "경상북도 민원실"로 발신
2. **통화 중**
   - 말풍선 실시간 누적. 말한 것은 **말하는 중에도** 채워진다(중간 결과).
   - **표준어 대비 표시는 없다.** 한국인은 사투리를 그냥 알아듣는다 — 굳이 표준어로 바꿔
     보여주면 없는 문제를 만들어낸 것처럼 보인다. 정규화는 서버 안에서 계속 돌아간다
     (라우팅 정확도가 거기 달려 있다). 화면 표시만 뺀 것이다.
   - 어르신 모드는 말풍선 목록 대신 **자막 두 줄**(위=민원실 / 아래=나)만 보여준다.
   - STT 원문·정규화 결과·보낸 텍스트는 오류 추적용으로 **콘솔(`console.debug`)** 에만 남는다.
   - 하단 슬롯 4칸(무슨 일 / 어디서 / 언제부터 / 연락처)이 대화에 따라 채워진다.
   - 우상단 칩에 **지금 쓰는 음성 입력 경로**가 표시된다.
3. **결과** — 민원카드 + "담당자에게 전달됨" 상태 전환. 담당 부서와 **연결 근거(사무분장 원문)** 포함.

주장이 아니라 실측값이다. 자세한 표는 [`docs/ACCESSIBILITY.md`](../../docs/ACCESSIBILITY.md).

합성 후 실제 색으로 쟀다 — 그 처리 때문에 "듣는 중…" 이 2.47:1 이던 것을 잡았다.

## 서버(P6)와의 약속

**요청** — 계약서 5절 필드는 그대로 보낸다. 여기에 **추가 필드 하나**를 얹었다.

```jsonc
POST /api/call/turn
{
  "session_id": "...",
  "text": "재점수화로 고른 문장",        // 계약 그대로. 서버가 alternatives 를 몰라도 이것만 쓰면 된다
  "alternatives": [                      // 추가 필드 — 모르면 무시하면 된다
    {"transcript": "...", "confidence": 0.91},
    {"transcript": "...", "confidence": 0.83}
  ]
}
```

`alternatives` 는 **하위호환**이다. 서버가 이 필드를 알면 `voisso.dialect` 로 다시 골라
`text` 보다 나은 후보를 쓸 수 있다(브라우저는 사전 발췌만 갖고 있고, 서버는 전체를 갖고 있다).
끄려면 `config.js` 의 `SEND_ALTERNATIVES: false`.

**응답** — 관대하게 읽는다. 아래는 주면 UI 가 더 잘 보여주는 값들이다.

| 필드 | 쓰임 |
|---|---|
| `reply_dialect`, `reply_text` | 상담원 말풍선. 하나만 와도 됨 |
| `slots` | 하단 슬롯 4칸 (`what/where/when/contact` 권장, 별칭도 매핑) |
| `audio_b64` | 있으면 재생, 없으면 텍스트만 (= 텍스트 모드 정상 동작) |
| `done` | true 면 "통화 끝내고 민원 접수" 버튼이 강조된다 |
| **`caller_turn`** | **발신자 발화. 계약 5절의 정본이며 이 UI 의 1순위 소비 대상이다.** 아래 참조 |
| `caller_text` / `caller_standard` | 하위호환. 새 서버는 `caller_turn` 만 채우면 된다 |

### `caller_turn` — 전사 표시의 정본

```jsonc
"caller_turn": {
  "dialect":      "비만 오모 물이 안 빠지가…",   // 어르신이 말한 그대로 (화면 본문)
  "standard":     "비만 오면 물이 안 빠져서…",   // normalize() 결과 (정규화 후 줄)
  "source":       "stt" | "text",
  "stt_raw":      "비만 오면 물이 안 빠졌다…",   // 받아쓴 원본 (콘솔 진단용)
  "stt_provider": "openai" | "web" | "text"      // 말풍선 머리말의 경로 표시에 쓴다
}
```

**이 필드가 없으면 화면은 그 사실을 감추지 않는다.**
음성 입력인데 `caller_turn` 이 없으면 프론트에는 표시할 텍스트가 아예 없다.
- 시연 모드: 빨간 점선 말풍선 + `⚠ 서버가 caller_turn 을 주지 않음`
- 어르신 모드: "잘 못 알아들었습니더. 다시 말씀해 주이소."
- 두 모드 모두 콘솔에 `[Voisso] 서버가 caller_turn 을 주지 않았습니다. 응답 필드: …` 경고

**요청에 함께 보내는 추가 필드** (계약 필드는 그대로, 모르면 무시해도 된다)

| 필드 | 언제 | 뜻 |
|---|---|---|
| `stt_provider` | 브라우저 음성인식으로 받아쓴 경우 `"web"` | 서버가 `caller_turn.stt_provider` 를 그대로 채우면 된다 |
| `alternatives` | 후보가 2개 이상일 때 | `[{transcript, confidence}]` — 서버가 방언 사전으로 다시 고를 수 있다 |

> **P6에게 — 지금 비어 있는 한 칸.**
> `voisso/agent/session.py` 의 `turn()` 은 이미 `caller_dialect` 와
> `caller_standard = integrations.normalize(...)` 를 계산해 `self.transcript` 에 넣는다.
> 그런데 `_say()` 가 만드는 **응답에는 그 두 값이 없다.** 그래서 실서버로 붙이면
> 통화 화면에서 "STT 원문 → 방언 정규화" 비교가 **빈칸으로 뜬다**(데모 스크립트 1단계의 핵심 컷).
> `_say()` 반환 dict 에 아래 한 줄만 얹어 주면 UI 쪽은 수정 없이 바로 붙는다.
>
> ```python
> last = next((e for e in reversed(self.transcript) if e.get("role") == "caller"), None)
> ...
> "caller_turn": {"dialect": last["dialect"], "standard": last["standard"]} if last else None,
> ```
>
> 계약서 5절의 기존 필드는 건드리지 않는 **추가 필드**다.

`start` 응답에 첫 인사를 얹어 주는 것(P6이 이미 함)은 UI 가 그대로 활용한다. 없으면 `turn` 을
`text: ""` 로 한 번 호출해 인사를 받아온다.
