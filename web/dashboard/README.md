# Voisso 민원 담당자 대시보드 (`web/dashboard/`)

경상북도청 민원 담당 공무원이 **AI가 접수·배정한 민원카드를 확인하고, 배정 근거를 검증하고,
필요하면 즉시 재배정**하는 실무 화면이다.

설계 원칙 하나: **근거 없는 배정은 공공기관에서 쓰이지 않는다.**
그래서 모든 민원카드에서 `assigned.evidence`(경상북도청 사무분장 담당업무 원문)를
상세 화면 최상단의 인용 블록으로 크게 노출한다.

## 실행

빌드 스텝도, 의존성도, `node_modules`도 없다.

```bash
# 권장 — 서버가 대시보드를 함께 서빙한다 (같은 오리진이라 설정이 필요 없다)
python -m server                       # 포트는 server/config.py 의 VOISSO_PORT
# -> http://127.0.0.1:<VOISSO_PORT>/dashboard/

# 서버 없이 화면만 보려면 (샘플 데이터로 동작)
open web/dashboard/index.html          # macOS
xdg-open web/dashboard/index.html      # Linux
```

> **포트 규칙(팀 합의):** `8111` 은 사용자 미리보기 전용이라 절대 쓰지 않는다. `8000` 도 쓰지 않는다.
> 에이전트별 테스트 포트는 P3=8020 · P4=8021 · P5=8022 · P6=8023 · P7=8024 · **P8(대시보드)=8025**.
> 대시보드를 따로 띄워 실서버에 붙일 때는 `?api=http://127.0.0.1:8023` 처럼 주소를 명시한다.

## 설정 — `config.js`

실행에 관한 건 전부 여기 한 파일에 모여 있다.

```js
USE_MOCK: false            // true 면 서버를 찾지 않고 샘플로만 돈다 (오프라인 시연)
API_BASE: ""               // "" = 이 화면을 서빙하는 서버와 같은 오리진
API_FALLBACKS: [...]       // 다른 포트에서 대시보드만 열었을 때 찾아볼 주소
POLL_INTERVAL_MS: 4000     // 자동 갱신 주기
NEW_BADGE_TTL_MS: 300000   // NEW 뱃지 유지 시간
```

URL 로도 덮어쓸 수 있다 — 데모 중에는 이쪽이 빠르다.

| 쿼리 | 효과 |
|---|---|
| `?mock=1` | 서버를 무시하고 샘플 데이터로 강제 전환 |
| `?api=http://127.0.0.1:8023` | API 주소 고정 (지정하면 다른 서버로 폴백하지 않는다) |
| `?poll=2000` | 폴링 주기 변경 |
| `?theme=dark` | 화면 모드 고정 |

## 데이터 출처 — 자동 전환

`app.js` 는 기동 시 계약서 5절의 API를 순서대로 탐색해 처음 응답하는 곳에 붙는다.

1. `API_BASE` (기본 `""` = 현재 오리진. `server/main.py` 가 `/dashboard` 로 마운트하므로 운영 기본값)
2. `API_FALLBACKS` (**기본 빈 배열**) — 포트를 추측해 찔러보지 않는다. 따로 열어야 하면 `?api=` 로 명시한다.

전부 실패하면 `mock-data.js` 의 샘플 민원 6건으로 폴백하고, 우상단 뱃지가
`● 샘플 데이터`(주황)로 바뀐다. 실제 서버에 붙으면 `● 실시간 연결됨`(초록)이 된다.
**데모 당일 서버가 안 떠도 화면은 그대로 보인다.**

붙어 있던 서버가 도중에 끊기면 화면을 비우지 않는다. 마지막으로 받은 목록을 그대로 두고
뱃지만 `● 연결 끊김 — 재시도 중`(빨강)으로 바꾼 뒤, 다음 폴링에서 자동 복구한다.

소비하는 엔드포인트:

| 메서드 | 경로 | 용도 |
|---|---|---|
| GET | `/api/complaints` | 목록·통계·필터 · 폴링 |
| GET | `/api/complaints/{id}` | 카드 선택 시 상세 재조회 |

> **P6 참고:** 대시보드를 서버와 다른 포트에서 열면 브라우저 CORS가 걸린다.
> `server/` 가 `web/dashboard/` 를 `/dashboard` 로 서빙하므로 기본 경로에서는 문제가 없다.

## 자동 갱신 (데모 4단계)

`POLL_INTERVAL_MS`(기본 4초)마다 `/api/complaints` 를 다시 받는다.
**통화가 끝나면 새로고침 없이 목록 맨 위에 뜬다.**
HTTP 실측: `/api/call/end` 응답 이후 목록 API 반영까지 **0.053초** (서버가 원자적 쓰기 후
매 요청마다 디렉터리를 다시 읽으므로 캐시 지연이 없다).

- 새로 들어온 민원에 빨간 **NEW** 뱃지 (카드를 열어보면 사라진다)
- 도착 순간 카드가 한 번 짧게 번진다(1.6초, 반복 없음). `prefers-reduced-motion` 이면 생략
- `새 민원 접수 — #0004 …` 토스트
- 상단바에 마지막 갱신 시각 표시

폴링이 선택·스크롤·필터·검색어를 건드리지 않는다. 담당자가 상세를 읽는 중에
목록이 갱신돼도 보던 화면이 흔들리지 않는다.

### 폴링 부하를 줄이는 세 가지

하루 종일 열어 두는 화면이라 조용한 시간의 요청이 그대로 서버 비용이 된다.

1. **탭이 백그라운드면 폴링을 멈춘다.** 돌아오면 즉시 한 번 당겨온다.
2. **적응형 주기** — `POLL_IDLE_AFTER_MS`(2분) 동안 아무 변화가 없으면 `POLL_IDLE_MS`(15초)로
   늦춘다. 새 민원이 들어오거나 담당자가 화면을 만지면 즉시 4초로 돌아온다.
   담당자 1명 8시간 기준 7,200 → 3,240 req/day (**55% 감소**).
3. **조건부 요청** — 서버가 `ETag` 를 주면 `If-None-Match` 를 실어 보내고, `304` 가 오면
   본문을 파싱하지도 렌더하지도 않는다. 서버가 아직 `ETag` 를 안 주면 헤더는 무시되므로
   지금 켜 두어도 안전하다. **서버가 지원하는 순간 전송량이 231MB/day → 2.7MB/day 가 된다.**

> 3번은 서버(P6) 변경이 필요하다. 제안서는 `docs/` 가 아니라 오케스트레이터에게 전달했다.

## 긴 텍스트가 칸을 뚫지 않게

한국어는 단어 경계가 애매해서 `word-break: keep-all` 만 두면 긴 문자열이 컨테이너를 넘어간다.
사용자 제보(“각 칸이 한 줄에 너무 길면 UI 가 삐져나온다”)의 원인이 이것이었다.

```css
body { word-break: keep-all; overflow-wrap: anywhere; }
```

평소에는 단어를 지켜 읽기 좋게 두고, **넘칠 때만** 강제로 끊는다.
`anywhere` 는 `min-content` 계산에도 반영돼 flex·grid 자식이 실제로 줄어들 수 있게 해 준다.

여기에 더해:

- **flex·grid 자식 59곳에 `min-width: 0`.** 기본값이 `auto` 라 내용보다 작아지지 못하는데,
  긴 부서명·요약이 칸을 밀어내는 가장 흔한 원인이다.
- 넓은 표(통화 전문·처리 이력)는 `.scroll-x` 로 감싸 **자기 컨테이너 안에서만** 가로 스크롤한다.
  페이지 전체가 가로로 밀리지 않는다. `body { overflow-x: hidden }` 같은 꼼수는 쓰지 않았다
  (내용을 잘라 감추는 것이라 원인을 덮을 뿐이다).
- 줄어들지 않던 가로 그룹(처리 상태 바, 전사 모드 전환, 카드 상단, 후보 부서 우측)에 `flex-wrap`.
- 뱃지는 `max-width: 100%` + 말줄임, 태그는 줄바꿈 허용.

좁은 창 대응은 `.stats` 3열(≤1400) → 2열(≤1100), `.layout` 1열(≤860),
`.hist-row`·`.alt` 열 축소(≤1180) 로 처리한다.

## 긴 배정 근거 처리

실데이터의 근거는 `◦ 하수도정비기본계획(변경) 수립 ◦ 공공하수처리시설 설치인가 ◦ …`
처럼 길다. 대시보드는 이를 항목 단위로 쪼개 목록으로 렌더하고,
**첫 항목은 접힌 상태에서도 항상 보인다.** 나머지는 `근거 N줄 더 보기 ▼` 로 펼친다.
항목으로 안 쪼개지는 긴 문장은 2줄에서 자르고 같은 방식으로 펼친다.

## 긴급도 (계약 5-A)

담당자는 하루에 수십 건을 받는다. 무엇을 먼저 볼지 정해 주지 않으면 접수 순서대로 처리되고
급한 민원이 뒤에 묻힌다. 그래서 `응급 / 중요 / 보통 / 낮음` 을 목록·상세·현황 세 곳에 모두 건다.

### 정렬을 이렇게 정한 이유

**기본은 최신순 + 응급만 상단 고정이다.** 긴급도 전체 정렬을 기본으로 하지 않았다.

- 담당자에게 목록은 **작업 큐**다. “위가 최신” 은 1초면 익히는 규칙이고,
  통화가 끝나자마자 새 민원이 맨 위에 뜨는 동작이 이 화면의 실시간성 그 자체다.
- 긴급도로 전부 정렬하면 방금 들어온 `보통` 이 목록 중간에 끼어 **보이지 않는다.**
  새 민원 도착 표시(NEW 뱃지·하이라이트)도 같이 죽는다.
- 그래서 예외를 하나만 둔다 — **응급**. “사람이 다칠 수 있다. 지금” 은 스크롤해서
  찾게 두면 안 되므로 무조건 위로 올린다.
- 밀린 건을 훑을 때는 목록 머리의 `최신순 / 긴급도순` 토글로 바꾼다.
  특정 단계만 볼 때는 상태 필터의 `긴급도` 그룹이 더 빠르다.

### 색만으로 구분하지 않는다

색각 이상을 가진 담당자가 있다. 모든 표시에 **라벨 글자**를 함께 쓰고, 색이 아닌 단서를 겹친다.

| 위치 | 색 아닌 단서 |
|---|---|
| 목록 카드 | `응급` `중요` **글자 뱃지** + 왼쪽 테두리 두께(6px / 4px) + 응급은 `❗` |
| 상세 | 큰 라벨 글자 + 테두리 2px + 단계 뜻(“사람이 다칠 수 있다. 지금”) |
| 현황 위젯 | 단계 이름과 숫자를 함께 표기 |

**깜빡이는 애니메이션은 넣지 않았다.** 하루 종일 보는 화면이다.

### reason 을 반드시 보여 준다

배정 근거(`evidence`)와 같은 원칙이다. `▍이 판정의 근거` 아래에 `reason` 을 그대로 싣고,
`signals`(감지 신호)를 태그로 붙이고, 규칙 판정인지 AI 문맥 판정인지도 표시한다.
담당자가 “왜 응급인가” 를 납득하지 못하면 그 표시는 무시되고, 무시되면 없는 기능과 같다.

### 담당자가 고칠 수 있다

`긴급도 조정` → 4단계 중 선택(+ 조정 사유). **AI 판정은 제안이고 최종 판단은 사람이 한다.**

- 서버에 `POST /api/complaints/{id}/urgency` 가 있으면 그쪽에 쓴다 — 모두에게 반영된다.
  서버가 `urgency.history` 에 원래 판정과 근거를 남기고, 대시보드는 그것을 읽어
  `AI 최초 판정: 응급 — …` 으로 보여 준다.
- 서버가 없거나 저장에 실패하면 브라우저 casebook 에만 남기고 그 사실을 토스트로 알린다.
- 어느 경로든 **처리 이력**에 `긴급도 응급 → 중요` 로 기록되고, AI 근거와 담당자 사유가 함께 남는다.
  담당자가 AI 판정을 얼마나 자주 뒤집는지가 곧 판정 품질 지표다(재배정 비율과 같은 구조).

### safety_referral

응급으로 판정되면 통화 중 119·112 안내가 먼저 나간다. 그 기록이 있으면 **상세 화면 최상단**에
`안전 안내 — 통화 중 119 안내를 이미 드렸습니다 (소방·구조)` 를 띄우고,
`민원 접수가 신고를 대체하지 않습니다` 를 함께 적는다.
담당자가 이걸 모르면 중복 안내하거나, 더 나쁘게는 아무도 신고하지 않았다고 착각한다.
목록 카드에도 `119 안내함` 뱃지가 붙는다.

### 현황 위젯

`오늘 접수` 바로 다음에 **응급 건수**를 큰 숫자로 두고, 그 아래 4단계 분포와
`담당자 조정 N건` 을 함께 보여 준다. 서버가 아직 판정을 주지 않으면 `–` 와 `서버 판정 대기` 로
표시한다 — 0 이라고 거짓말하지 않는다.

## 어르신이 덧붙인 말 (`notes`)

통화 종료 직전 “더 하실 말씀 있으실까예?” 에서 나온 발화가 민원카드의 `notes` 에 쌓인다.

```json
"notes": [{"text": "아침에만 그래예", "at": "...", "source": "caller"}]
```

슬롯(무엇·어디·언제·연락처)에 안 맞는 정보 — “아침에만 그래예”, “옆집도 같이 그래예” — 가
담기는데, **현장에 나가는 담당자에게는 요약보다 쓸모 있을 때가 많다.**
그래서 통화 전문 안에 묻어 두지 않고 **배정 근거 바로 다음, 통화 잇기 앞**에 따로 세운다
(담당자가 연결하기 전에 읽어야 할 맥락이기 때문).

- 출처(`source`)는 우리말로 바꿔 표시한다: `caller`→신고자, `callback`→안내 전화 문의,
  `handoff`→담당자 통화, `agent`→AI 상담. (진행 안내 전화에서 나온 질문이 여기 쌓인다.)
- 검색 대상에도 포함된다.
- 서버가 아직 `notes` 를 안 보내면 섹션이 나오지 않고, 빈 배열이면 “없음”으로 표시한다.
- CSV 열에는 넣지 않았다 — 필요하면 알려 달라.

## 담당자 핸드오프 (계약 5-B) — 이 화면의 핵심

**AI 가 접수하고, 사람이 이어받는다.** 공공기관은 AI 에 전권을 주지 않는다.
접수까지는 AI, 그 다음은 담당자가 책임진다.

민원 상세의 `☎ 통화 잇기` → 담당자 이름·부서 입력(부서는 **배정된 부서가 기본값**) →
`POST /api/handoff/{id}/start` → 어르신 화면에 담당자 인사가 **사투리로** 뜬다.

### 담당자는 표준어만 쓰면 된다

이 기능의 값어치는 여기 있다. **담당자가 경상도 사람이 아니어도 어르신과 대화할 수 있다.**

| | 담당자가 보는 것 | 어르신이 보는 것 |
|---|---|---|
| 담당자 입력 | `접수 내용 확인했습니다` (직접 친 표준어) | `접수 내용 확인했심더` |
| 어르신 발화 | `아이고 고맙습니다. 언제쯤 오시나요?` | `아이고 고맙심더. 언제쯤 오시는교?` |

담당자 화면은 항상 **표준어**로 보여 주고, `사투리 원문 보기` 토글로 어르신이 실제로 한 말을
대조할 수 있다. 담당자가 보낸 말도 `어르신에게 전달된 사투리` 토글로 확인된다.
화면 상단에 **"표준어로 입력하시면 사투리로 전달됩니더"** 를 띄워 이 사실을 드러낸다.

변환은 서버의 `voisso/dialect` (`normalize()` / `to_dialect()`)가 한다.
각 메시지는 `dialect` 와 `standard` 를 둘 다 담으므로 양쪽 화면에서 원문 대조가 가능하다.

### AI 는 발화를 멈춘다

핸드오프가 열리면 화면에 `지금부터 담당자가 직접 응대합니더` 를 명시한다.
누가 말하는지 헷갈리면 그 자체로 신뢰 문제가 되기 때문이다(계약 5-B 규칙).

### 담당자 실명은 남지 않는다

- 이름은 **어르신 화면에 표시하기 위한 용도**로만 서버에 보내고, 서버가 `홍○○` 로 마스킹해 저장한다.
- 대시보드는 이름을 **localStorage 에도 저장하지 않는다.** 새로고침하면 지워진다.
  (부서는 개인정보가 아니므로 다음 연결 때 자동으로 채워지도록 남긴다.)
- **CSV 에도 담당자 열이 없다.**

### 지금 나를 기다리는 사람 — 연결 대기 알림

어르신은 통화를 끝낸 뒤 **화면 앞에서 담당자 연결을 기다린다.**
그런데 `미연결` 은 과거 민원 전부의 기본값이라 그것만으로는 신호가 되지 않는다(소음이 된다).

그래서 **접수된 지 얼마 안 됐고(기본 15분, `HANDOFF_WAIT_WINDOW_MS`) 아직 아무도 연결하지 않은 건**
만 골라 `연결 대기` 로 다룬다. 이미 완료·반려한 건은 기다릴 사람이 없으므로 뺀다.

- 목록 맨 위에 **알림 띠**: `연결 대기 N건 — 어르신이 화면 앞에서 담당자 연결을 기다리고 있을 수 있습니다`
  누르면 그 건만 걸러 보고, 다시 누르면 전체로 돌아온다. 대기가 없으면 띠 자체가 사라진다.
- 해당 카드에만 `☎ 연결 대기` 뱃지 + 왼쪽 주황 테두리.
- 상단 현황 부제에 `연결 대기 N건`, 상태 필터에 `연결 대기 (어르신이 기다리는 중)`.
- 새 민원 도착 안내(스크린리더)도 “어르신이 담당자 연결을 기다리고 있을 수 있습니다” 로 읽어 준다.

그 밖의 핸드오프 상태는 `● 통화중` / `상담종료` 뱃지로 표시한다.
통화 중인 카드는 왼쪽 테두리가 청록색이 되고 접수번호 옆에 점이 붙는다.

### 중복 메시지 방어

서버에서 같은 메시지가 두 번 조회되는 문제가 있었다(P6 수정 중).
화면에 같은 말이 두 번 뜨면 담당자가 “내가 두 번 보냈나” 를 의심하게 되므로,
**역할·본문·시각이 완전히 같은 메시지는 하나로 접어서** 보여 준다.
같은 말이라도 시각이 다르면 실제로 두 번 말한 것이므로 그대로 둔다.
서버가 고쳐진 뒤에도 이 처리는 무해하다.

목록 상태는 `GET /api/complaints` 응답의 `handoffs` 맵에서 온다(**추가 요청 0회**).
대시보드는 이 필드의 존재로 서버의 핸드오프 지원 여부까지 판정한다.

### 서버가 없을 때

`handoff-mock.js` 가 계약 5-B 를 브라우저 안에서 그대로 흉내낸다(방언 변환 축약판 포함).
패널에 `목 모드` 표시가 붙고, 서버가 뜨면 **코드 수정 없이** 실 API 로 전환된다.

### 폴링

어르신 답변은 `GET /api/handoff/{id}` 폴링으로 받는다. **주기는 민원 목록 폴링과 같다.**
통화가 열려 있는 동안에는 유휴 백오프가 걸리지 않도록 활동 상태로 유지한다.

## 진행 안내 콜백 (계약 5-C) — 시스템이 먼저 전화를 건다

지금 어르신이 민원 진행 상황을 알려면 **다시 전화해서 ARS 를 또 뚫어야 한다.**
우리가 없애려던 벽을 어르신이 다시 만난다. 그래서 방향을 뒤집는다.

담당자가 상세 화면에서 **진행 상황을 표준어로 쓰고** `☎ 안내 전화 걸기` 를 누르면,
어르신 화면에 수신 전화가 뜨고 AI 가 그 문장을 **사투리로 읽어 준다.**

### AI 는 담당자가 쓴 것만 전달한다

이 기능에서 가장 중요한 제약이다. 처리 결과·일정·가능 여부를 AI 가 만들어 내면
그건 **행정 약속**이 된다. 그래서 화면이 두 가지를 강제로 보여 준다.

1. **원문 ↔ 사투리 대조** — 담당자가 쓴 표준어와 어르신께 실제로 전달된 사투리를
   나란히 놓는다. “내가 쓴 대로 갔는가” 를 눈으로 확인할 수 있어야 한다.
   그 아래에 `AI 는 위 문장을 사투리로 바꿔 읽었을 뿐입니다. 새로 만든 내용은 없습니다` 를 못박는다.
2. **어르신 추가 질문** — AI 는 답하지 않는다. 브리핑에 없는 질문은
   `담당자에게 여쭤보고 다시 연락드릴게예` 로 넘기고, 질문은 이 화면에 쌓인다.
   `AI 가 답하지 않았습니다. 담당자 확인이 필요합니다` 라고 명시하고,
   `이 질문에 답해 다시 안내하기` 를 누르면 질문을 인용한 새 브리핑 작성으로 이어진다.
   (답은 언제나 담당자가 쓴다.)

작성 폼에도 같은 경고를 띄운다 — “AI 는 여기 쓰신 내용만 전달합니다.”

### PSTN 은 아직이다

**실제 전화망 연동은 다음 단계다.** 지금은 어르신 화면에 수신 화면을 띄우는 시뮬레이션이다.
패널 하단에 이 문장을 항상 표시한다. 숨기면 질문 하나에 무너진다.

### 상태와 목록 표시

`안내 없음` → `안내 대기`(어르신 수신 대기) → `안내 통화중` → `안내 완료`.
조치가 필요한 `안내 대기` / `안내 통화중` 만 목록 카드에 `☎` 뱃지로 띄우고,
상태 필터의 `진행 안내 전화` 그룹과 상단 현황 부제(`안내 N건 진행`)에서도 확인된다.

### 서버가 없을 때

`callback-mock.js` 가 계약 5-C 를 브라우저 안에서 흉내낸다. **이 목도 답을 지어내지 않는다** —
브리핑을 사투리로 변환해 재생할 뿐이고, 그 밖의 질문에는 회피 문구를 쓴다.
서버가 뜨면 코드 수정 없이 실 API 로 전환된다.

> **P6 요청:** `GET /api/complaints` 응답에 `handoffs` 처럼 `callbacks` 맵(`{민원번호: 상태}`)을
> 얹어 주면 목록 뱃지를 **추가 요청 0회**로 그릴 수 있다. 대시보드는 이미 그 필드를 읽도록 되어 있고,
> 없으면 목으로 폴백한다.

## 화면 구성

- **상단 현황** — 오늘 접수 / **응급(긴급도 분포)** / 미확인 / **담당자 통화중** / 미배정 / **AI 배정 대비 재배정 비율** / 부서별 분포
- **좌측 목록** — 접수번호, 시각, 통화시간, 요약, 배정 부서, 상태 뱃지 (최신순)
- **우측 상세**
  - 요약·분류·접수시각·통화시간
  - **배정 부서 + 직위 + 연락처 + 배정 근거 원문(인용 블록)**
  - **긴급도** — 단계 · 판정 근거 · 감지 신호 · 담당자 조정 (safety_referral 은 최상단)
  - **처리 상태 바** — 접수됨 → 확인함 → 처리중 → 완료 / 반려
  - **어르신이 덧붙인 말(notes)** — 슬롯에 안 담긴 추가 발화
  - **담당자 통화 패널** — 통화 잇기 / 표준어 입력 / 사투리 대조 / 종료
  - **진행 안내 전화** — 진행 상황 작성 / 원문↔사투리 대조 / 어르신 추가 질문
  - 후보 부서와 매칭 점수 → `이 부서로 재배정` 한 번 클릭
  - **처리 이력** — AI 최초 배정(근거 포함)과 담당자의 모든 개입 기록
  - 통화 전문 **[사투리 원문 | 표준어] 나란히 대조** (단독 보기 전환 가능)
  - 신고자 정보 (마스킹된 값만)

### 두 가지 상태 축

**처리 상태** — 담당자가 직접 옮기는 값. 상세 화면의 처리 상태 바에서 바꾼다.

| 상태 | 의미 |
|---|---|
| 접수됨 | 아직 아무도 열어보지 않음 (= 상단 '미확인' 집계 대상) |
| 확인함 | 담당자가 내용을 확인함 — **목록에서 카드를 열면 자동 전이** |
| 처리중 | 현장 확인·조치 진행 중 |
| 완료 | 조치 완료, 민원인 회신됨 |
| 반려 | 타 기관 이관 등으로 종결 |

자동 전이는 **담당자가 직접 카드를 클릭했을 때만** 일어난다. 화면 진입 시의 자동 선택은
확인으로 치지 않는다 — 그렇지 않으면 '미확인 건수'가 거짓말을 한다.

**배정 상태** — 데이터에서 파생된다. 담당자가 고르는 값이 아니다.

| 상태 | 조건 |
|---|---|
| 재배정 | 담당자가 AI 배정을 다른 부서로 바꿈 |
| 미배정 | `assigned` 가 없거나 `full_name` 이 비어 있음 / `미배정` |
| 배정완료 | 그 외 |

### 재배정 이력과 라우팅 품질 지표

담당자가 후보 부서를 클릭하면 배정이 바뀌지만 **AI 최초 배정과 그 근거는 지워지지 않는다.**
`처리 이력` 섹션에 시간순으로 남고, 후보 목록에서도 `AI 최초 배정` / `담당자 이전 배정`
표식으로 구분된다. `↩ AI 배정으로 되돌리기` 로 언제든 복구할 수 있고, 되돌린 사실도 이력이 된다.

이력을 남기는 이유는 감사 추적만이 아니다. **담당자가 AI 배정을 얼마나 자주 뒤집는지가
우리 라우팅 품질의 지표**이기 때문이다(GOAL.md H3: 재배정 20% 미만). 상단 현황의
`AI 배정 대비 재배정 비율` 이 그 값을 그대로 보여 준다.

```
분모 = AI 가 실제로 부서를 배정한 민원 수 (미배정 건은 제외)
분자 = 담당자가 그 배정을 바꾼 민원 수
```

20% 이상이면 숫자와 게이지가 경고색으로 바뀐다. 우리에게 불리한 값이어도 숨기지 않는다.

### ⚠️ 담당자 입력값은 현재 브라우저에만 저장된다

처리 상태·재배정·이력은 **그 브라우저의 `localStorage`** 에만 남는다(`voisso.dashboard.casebook.v1`).

- 다른 PC·다른 브라우저에서 열면 보이지 않는다.
- 브라우저 데이터를 지우면 사라진다.
- 서버의 민원카드 원본은 바뀌지 않는다.

계약서 5절에 배정·상태 변경 API가 없어서 그렇다. **실제 운영 전에 반드시 서버 저장으로 옮겨야 한다.**

> `app.js` 의 `setWorkflow()`, `reassign()`, `undoReassign()`, `saveBook()` 네 곳에서만
> 호출을 추가하면 된다. 저장 구조(`{workflow, assignment, history}`)는 그대로 서버로 옮길 수 있게 짜 두었다.

## CSV 내보내기

툴바의 `⤓ CSV 내보내기` → **현재 필터 결과** 또는 **전체 민원** 중 선택한다.
빌드 스텝 없이 `Blob` + `URL.createObjectURL` 로 저장하며 외부 의존성은 없다.

- **UTF-8 BOM** 을 붙인다. 없으면 엑셀에서 한글이 깨진다 (스크레이퍼 CSV 와 동일한 처리).
- 줄바꿈은 엑셀 호환을 위해 **CRLF**, 값 안의 `,` `"` 는 표준 방식으로 이스케이프한다.
- 파일명: `voisso_민원목록_20260822_0155_필터.csv`

| 열 | 비고 |
|---|---|
| 접수번호 / 접수일시 / 통화시간 / 요약 / 분류 | |
| 배정부서 / 배정근거 | 재배정했으면 재배정된 값 |
| 상태 | 처리 상태 (접수됨/확인함/처리중/완료/반려) |
| 신고자연락처(마스킹) | **마스킹된 값만.** 원본 번호는 민원카드에도 없고 CSV 로도 나가지 않는다 |
| 재배정여부 / AI최초배정부서 | 재배정 비율을 엑셀에서 직접 검산하기 위한 추가 열 |

## 개인정보 처리 (계약서 3절 준수)

- **`phone_token` 은 화면에 절대 노출하지 않는다.** 대시보드는 번호를 생성하지도 않는다.
- 서버가 `resolve_phone()` 으로 해석한 실번호를 카드에 얹어 주면(`assigned.phone`)
  그 값을 표시하고, 없으면 경북도청 대표번호 **1522-0120** 으로 안내한다
  (`대표번호 안내` 표기).
- 신고자 정보는 `name_masked` / `phone_masked` 만 표시한다.

> **현재 서버는 토큰을 풀어 주지 않는다.** `voisso/agent/complaint.py` 의 카드 빌드에서
> `integrations.resolve_phone(phone_token)` 을 호출해 `assigned["phone"]` 으로 실어 주면
> 대시보드가 즉시 실번호를 표시한다(프론트 수정 불필요).
> 실번호 매핑은 서버에만 두고 브라우저로 내려보내지 않는 것이 맞다.

| `R` | 새로고침 |

P7의 접근성 측정(`docs/ACCESSIBILITY.md` 8절)에서 지적된 항목을 모두 반영했다.

| 지적 | 조치 |
|---|---|
| 라이트 보조 텍스트 3.39~3.94:1 (35곳) | `--text-3` `#78818d` → **`#5c6570`** (4.85~5.91:1) |
| 다크 보조 텍스트 3.92:1 | `--text-3` `#7d8794` → **`#98a2b0`** (5.53~7.21:1) |
| 브랜드 마크 흰 글자 2.46:1 (다크) | 다크에서 잉크색 `#12161b` 로 반전 (7.38:1) |
| 컨트롤 높이 30px | `.btn` `.wfbtn` `.seg button` `input` `select` `.ev-toggle` **44px 이상** |
| `.list:focus` 에 `outline:none` | `:focus-visible` 에 포커스 링 복구 (마우스 클릭에는 그리지 않음) |
| `aria-live` 영역 0개 | `#live-region`(`role="status"`) 추가 — 새 민원 도착·처리 상태 변경·재배정을 읽어 준다 |
| 본문 14px / 태그 11px | 본문 **15px**, 최소 글자 **12px** |

추가로 목록을 `role="listbox"` + `role="option"` + `aria-selected` + `aria-activedescendant`
로 바꿔, 키보드로 이동할 때 선택이 스크린리더에 전달되게 했다.

> **아직 확인 못 한 것:** 위 변경은 색·크기 계산과 정적 검사로만 검증했다.
> Chrome 은 P7 전용이라 렌더링된 화면을 눈으로 보지 못했다. 컨트롤이 30 → 44px 로 커지고
> 본문이 15px 이 되었으므로 **툴바·처리 상태 바의 줄바꿈을 한 번 봐 줘야 한다.**
